# SPEC-T42a: netkeiba 7日間無料トライアルでの調教データ全量キャッシュ

起票: 2026-07-25 (Fable 5)。ユーザー決定: **2026-07-26 深夜1:00に無料トライアル登録・作業開始**。
トライアル期限は登録から7日 (〜8/2 1:00頃)。**本SPECの実装はトライアル開始前に完了させる**
(登録後の7日間は取得だけに使い、1時間も無駄にしない)。

**スコープはログイン対応キャッシュ・パーサー骨格・Stage 0手順・全量バックフィルまで。
特徴構築・モデル評価は対象外** (トライアル終了後にキャッシュ上で別SPEC。急ぐ必要がない)。

## 0. 設計原則 (T54cの直系)

- **immutable rawHTMLキャッシュが成果物のすべて**。ページに写っているもの (調教時計・評価・
  厩舎コメント・併せ相手等) は全部残る。パース精錬は後からいくらでもやり直せる
- 保存: `data/t42/raw/<カテゴリ>/<キー>.html` + `data/t42/manifest.sqlite`
  (url・取得時刻UTC・HTTP状態・SHA-256・パーサーバージョン)。**すべてgitignore**
- 一度書いたキャッシュは上書き禁止。再実行はHTTP 0件でキャッシュから再パース (テストで保証)

## 1. ログインセッション対応 (新規・最重要)

- クッキーはユーザーがブラウザから取り出し、**gitignore対象の
  `data/t42/netkeiba_cookies.json`** に置く (形式は実装者が定義し、置き方をreportに明記)。
  コミット・ログ出力・例外メッセージへの混入を絶対にしない
- **ペイウォール検知のfail-closed**: 取得したページが会員コンテンツを実際に含むか
  (調教時計等のセンチネル要素の存在) を確認してからキャッシュに書く。ログイン切れ・
  非会員ページを**immutableキャッシュに保存してしまう事故を構造的に防ぐ**
  (検知したら保存せずmanifestへ失敗記録・3回連続で全体停止しユーザーへセッション更新を要求)

## 2. 対象ページと優先順 (ability.db実測ボリューム)

| 優先 | ページ種別 | 分量 | 見込み時間 (1.05秒間隔) |
|---|---|---:|---:|
| 1 | レース別調教ページ 2021-2026H1 | 18,940レース | 約5.5時間 |
| 2 | 馬別調教全履歴 2021-2026H1出走馬 | 32,826頭 | 約9.6時間 |
| 3 | レース別調教 2018-2020 | 10,327レース | 約3時間 |
| 4 | 馬別 2018-2020拡張 | 14,130頭 | 約4時間 |

- URLパターン (レース調教ページ・馬別調教履歴) はStage 0で実物確認して確定する
- 優先1と2のどちらを主力にするかはStage 0の判定 (§3-2) に従う。**判定不能なら両方取る**
  (合計約22時間、日次分割で7日に収まる)
- レースID・馬ID列挙は既存 `backfill_*_netkeiba.py` の資産・ability.dbの
  (date, place, r) / horse から構成する

## 3. Stage 0 (登録直後・7/26 1:00〜、100リクエスト以内)

1. **ティア確認**: トライアル資格で調教詳細 (生時計・ラップ) が見えるか。
   **見えなければ即報告・停止** (ユーザーがトライアルを即解約できるように)
2. **遡及可否**: 2021年・2018年の過去レース/過去馬の調教が当時分まで見えるか。
   レースページと馬別ページのどちらに完全な生データ (調教日・コース・馬場・ラップ・
   一杯/馬なり・併せ相手) があるか → **主力ページ種別を確定**
3. **公開時刻の手がかり**: 調教データの掲載タイミング (前日夜か当日朝か) を示す情報が
   ページ内にあるか確認 (as-of結合の将来設計材料。なければ「不明」と記録するだけでよい)
4. 数十件でパーサー骨格の実地検証 (フィールド抽出率を報告)
5. **7/26は開催日**: Stage 0の少数取得のみとし、大規模バックフィルは開催終了・週次結果
   取り込み完了後 (7/26夜以降) または7/27 (月) から

## 4. バックフィル運用制約

- 1.05秒以上間隔・指数バックオフ・5件連続失敗で自動停止 (T54cと同一)
- **日次上限8,000リクエスト** (netkeiba日次制限への配慮。超えたらその日は終了し翌日再開)
- **共通排他ロック** (`t54c_sectional_laps.scrape_lock`) を取得してから実行 —
  週次結果取り込み・T54c・他のnetkeibaバックフィルと絶対に同時実行しない
- 進捗はmanifestに永続化し、中断からいつでも再開可能 (取得済みはスキップ)
- 実行順: 優先1→2→3→4。トライアル最終日 (8/1) は取り漏れ回収と整合監査のみ

## 5. テスト

1. キャッシュ命中時HTTP 0件
2. ペイウォール/ログイン切れページを**キャッシュに書かない**こと (fixtureで機械保証)
3. immutable上書き拒否・SHA-256整合検証 (T54cと同型)
4. クッキーファイル不在時の明確なエラー (内容を絶対にログへ出さない)
5. 日次上限・排他ロック・連続失敗停止
6. パーサー骨格: Stage 0で取得した実ページfixtureで主要フィールド抽出
7. `python -m pytest tests/ -q` 全体パス

## 6. 成果物

  リクエスト実行計画 (日割り)。以後バックフィル進捗を日次1行で追記
- キャッシュ実体 (`data/t42/`、ローカルのみ)
