# SPEC-T62b: 勝負レース度の表示専用ボード + prospectiveシャドー測定

起票: 2026-07-24 (Fable 5)。T62歴史足切りゲート通過 ([報告](../T62-race-selection-report.md)
上位モデル裁定) を受けた次工程。T62討議合意 (docs/T62-race-selection-discussion.md) の
「歴史通過→表示専用→シャドー実測→prospective採否」4段階の第2-3段階にあたる。

**実装者の担当は実装・テスト・蓄積開始確認まで。シャドー評価の実行はゲート到達後、
採否は上位モデル。凍結manifestの再学習・再調整は一切禁止。**

## 0. 位置づけ (動かせない前提)

- T62ゲート通過が付与したのは**表示専用+シャドー進出権のみ**。購入推奨・通知接続は不可
- 通知条件 (LINE=5分前×EV≥1.3、Discord/ブラウザ) は**不変**。通知関数3つ
  (`_send_line`/`_send_discord`/`refresh_and_alert`) のAST不変性確認を必須とする (T59d前例)
- **正式採否はprospectiveデータでのみ行う** (歴史数値の再利用禁止)

## 1. 凍結manifestの持ち出し (最初に実施)

T62のfreeze manifestは gitignore対象の `outputs/t62_result.json` 内にのみ存在する。

1. `outputs/t62_result.json` から `freeze_manifest` を抽出し、
   **`eval/t62_freeze_manifest.json` としてコミット対象に保存**する
2. 保存したファイルの `manifest_sha256`
   (`db8df644fc5025f91d1ae6a7c67fe394a02f690a54f73f8b6aeb4d445055b1f3`) が
   台帳 `T62-race-relative-confidence-v1-result` の記録と一致することをテストで恒久保証する
3. ランタイムはこのファイルだけを読み、係数・scaler・閾値 (0.008586849446545392) を使用。
   **いかなる再fit・閾値変更もしない** (manifest SHA検証をロード時に行い、不一致なら
   スコア表示を停止するfail-closed)

## 2. ライブスコア計算

- **モデル確率**: 本番稼働中の予測経路 (T45 candidate採用後の `win5_ml_model.json` 系) が
  cutoff時点で出す勝率ベクトルをそのまま使う。T62歴史評価のbase CL (backtest側) との
  モデル差は**既知の限界として台帳に登録**し、シャドーでスコア分布の歴史との乖離を実測する
  (再校正はしない — 実選定率ドリフトの測定自体がシャドーの目的の一つ)
- **市場確率**: 既存T17スナップショットループ (board_odds_snapshots系) のcutoff時点
  単勝オッズから 1/odds 正規化。**cutoff定義はT21/T59eと同一** (discussion合意)
- **11列の特徴**: T62の `compute_race_features` と同一定義。`hist_coverage` は
  ability.db (またはライブ側の同等走歴) から発走前情報のみで計算
- 対象母集団はT62と同一 (9R以降・平地・8頭以上・全馬オッズあり)。範囲外レースは
  スコア自体を計算しない (「対象外」表示)

## 3. 表示 (表示専用・言葉の規律)

- 既存ボード画面 (index_boards.html系) に「**本日の勝負レース度**」欄を追加:
  スコア値・選定フラグ (凍結閾値以上か)・対象外区分の3状態
- **表示文言の必須要件** (裁定の懸念④を正確に伝える):
  「このスコアは『人気上位馬をモデルが市場より正確に評価できている可能性』を示す指標であり、
  的中・回収を保証しない。歴史検証では優位が1-3人気帯に集中し、中穴・大穴帯ではむしろ悪化した」
  という趣旨の説明文を表示欄に常設する
- **禁止語彙テスト** (T59d前例): 表示出力に「買い」「推奨」「◎」「⭐」「勝負確定」等の
  購入誘導語が含まれないことを機械保証する

## 4. シャドー記録 (スキーマ)

ロギングDB (T17/T59eと同系) に新テーブル `race_confidence_snapshots` (列名明示INSERT):

```
race_confidence_snapshots(
  date, place, r, cutoff_at, snapshot_source,
  model_probs_json, market_odds_json,
  features_json,          -- 11列の値
  score, threshold, selected,   -- 凍結閾値での判定
  manifest_sha256,        -- ロード時検証済みの値
  created_at
)
```

- 結果 (勝馬・確定オッズ) は**書き込まない** (評価時に既存の結果テーブルとjoinする —
  スナップショット行を事後に更新しない、T59eと同じ思想)
- 取得失敗時は前回値を流用せず、その旨を記録 (T50/T59d/T54cと同じ)

## 5. シャドー評価 (蓄積ゲート付き・事前登録)

- **T39へ新実験 `T62b-race-selection-shadow-v1` を事前登録** (蓄積開始前に登録)。
  封入: `eval/t62_freeze_manifest.json` のSHA-256・評価ハーネスSHA・本SPECの評価定義
- **蓄積ゲート**: `race_confidence_snapshots` に **4開催日以上かつ200レース以上**
  (T21/T59eと同一基準) 蓄積されるまで、評価ハーネスは集計値を一切出力しない
  (read-onlyで件数のみ先読みしブロック、T59eと同型のfail-closed)
- ゲート到達後の必須計測 (裁定の懸念4点に対応):
  1. **選定/未選定それぞれの「モデル−市場」paired勝馬LogLoss差** (開催日block bootstrap)。
     市場確率はcutoffスナップショット由来 (歴史評価との定義差そのものを記録)
  2. **選定集合の市場top-kフロア** (k=1..4)
  3. **実選定率** (凍結閾値での選定割合の推移。歴史では20%→26-27%へドリフト)
  4. **人気帯分解** (1-3/4-8/9+、選定・未選定両方)
  5. cutoffオッズ vs 確定オッズの分布差 (T21と同じ問題意識の実測)
- **採否はこのSPECでは行わない**。蓄積が十分になった時点 (上位モデルが別途判断) で
  prospective採否を裁定する。参考ROIを計算する場合も表示・通知には一切接続しない (T59e前例)

## 6. 制約

- `combo_probs.py`・`win5_ml_model.json`・既存通知・既存EV表示ロジックは変更しない
  (ボードへの欄追加と、その欄のためのデータ提供コードのみ追加)
- ability.db への書き込み禁止 (読み取りのみ)。ロギングDBへの追記のみ
- suite再起動 (デプロイ) はレース非開催日に行う (ユーザーへ依頼)

## 7. テスト

1. manifest SHA検証: `eval/t62_freeze_manifest.json` のSHAが台帳記録値と一致・
   改竄時はロード拒否 (fail-closed)
2. スコア再現: manifestの係数・scalerで歴史サンプル入力からT62のスコア値を再現
3. 禁止語彙テスト (表示出力)
4. 通知関数3つのAST不変性
5. 蓄積ゲート未達時に評価ハーネスが集計を出力しないこと
6. スナップショット行が結果情報を含まないこと (as-of保証)
7. 対象外レース (8頭未満・障害・9R未満) にスコアを出さないこと
8. `python -m pytest tests/ -q` 全体パス
