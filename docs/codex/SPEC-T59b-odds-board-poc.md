# SPEC-T59b (P1): 全組合せオッズ取得可能性PoC (JRA公式 vs netkeiba無料)

起票: 2026-07-19 (Fable 5)。T59討議合意の実行第2弾。Stage 0型の取得可能性判定のみ —
**本実装・全量取得はしない**。

## 0. 前提と制約

- **課金は一切しない** (T59前提)。無料階層で全組合せボードが見えない情報源は不採用
- リクエスト礼節: 1秒以上間隔・**PoC総量は情報源あたり30リクエスト以内**・書き込み0
- netkeibaは日次制限を他タスクと共有する — **T22等のスクレイプ系タスクと同時に
  走らせない**。JRA公式は独立 (T50実績)
- 対象券種: **複勝・ワイド・馬連** (第1波)。三連複は取得量の桁の見積りのみ
  (第2波判断の材料)

## 1. 目的

T59のP3 (買い目表示: 予測確率 vs 実オッズの乖離) とP4 (シャドーのCLV/ROI集計) に必要な
**全組合せの発売オッズ**を、無料・安定・as-of保証つきで取得できるかを判定する。
現状の `odds_snapshots` は単勝・複勝上下限のみで不足 (T59討議 §既存資産)。

## 2. 調査項目 (両情報源で同一開催日について)

1. **所在と取得単位**: 券種別オッズページのURL規約 (レース単位か・ページネーションか)。
   JRA公式のオッズページとnetkeiba無料階層 (odds.netkeiba.com) の両方
2. **券種被覆**: 複勝 (全馬)・ワイド (全組合せ)・馬連 (全組合せ) が無料で全量見えるか。
   三連複の組合せ数とページ構造 (取得量見積りのみ)
3. **更新タイミングとas-of**: 表示オッズの更新頻度・タイムスタンプの有無・
   「確定オッズ」の確定時刻。**live取得時に取得時刻を自前で刻めば足りるか**
4. **過去分の取得可否** (副次): 過去開催日の全組合せ確定オッズがアーカイブで見えるか
   (見えるなら歴史検証の幅が広がるが、**必須要件ではない** — P2のλ校正は着順+単勝
   オッズで足りる。過去分不可でもprospective運用は成立する)
5. **リクエスト数見積り**: 1開催日 (3場・36R) の第1波3券種の必要リクエスト数と、
   30/10/2分前スナップショット運用 (T17と同型) に載せた場合の日次総量
6. **DOM/API安定性**: 構造の壊れやすさ・robots方針・エラー時の識別可能性

## 3. 判定 (報告して停止 — Go/No-Goは上位モデル)

- 推奨情報源1つ (または併用構成) と、その根拠
- **停止条件**: どちらの情報源でも無料で第1波3券種の全組合せが取れない場合は
  その時点で停止・報告 (T59計画のP3/P4を組み替える判断は上位モデル)
