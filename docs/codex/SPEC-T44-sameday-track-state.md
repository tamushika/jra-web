## 1. 目的と、禁止済み仮説との区別

同一開催日の**先行レースの確定結果だけ**から、その日その競馬場の馬場状態
(時計の出方・脚質傾向・内外傾向) をas-of推定し、馬固有特性との交互作用として
conditional logit へ与えた場合の増分を検証する。

**禁止済みの「前日馬場バイアス持続」(负の結果) とは別仮説である**:
- 使うのは**当日**の先行レースのみ。前日以前のレース結果を日次状態の入力にしない
  (履歴データは基準時計等のbaseline算出に、その開催日より前のas-of断面としてのみ使用)
- 状態は日をまたいで持ち越さない

## 2. データと利用可能性 (as-of規約 — 最重要)

ability.db `runs` の既存列のみ使用: date/place/r/umaban/rank/time_sec/agari_3f/
corner_4/condition/distance/track_type/total_horses 等。

### 2.1 「その時点で確定していた先行レース」の定義 (事前登録)

runsに発走時刻が無いため、レース番号による保守的規約を事前登録して使う:

- **単レース予測** (レース r): 同一開催日の**同場 r' ≤ r−1** を利用可能とみなす
  (中央競馬は約30-35分間隔で発走し、確定時計は数分で公表されるため、
  r−1 は r の予測時点 (5分前) までに確定済み)
- **WIN5用途** (共通cutoff = 第1対象レース発走5分前、T39準拠): 全対象レースについて
  「**各場の r' ≤ (第1対象レースのレース番号 − 2)**」だけを利用可能とみなす
  (場間の発走時刻ずれ±10分程度を吸収する保守マージン)
- **感度分析必須**: 上記を r−2 / 第1対象−3 に厳格化した場合の結果を併記する
  (結論が規約に依存しないことの確認)
- 当該レース自身と同時刻以降のレースの混入はテストで禁止を保証する

## 3. 日次状態の推定 (venue-day × 芝/ダ 別)

先行レース集合 S (件数 n) から以下を推定する。**全て少サンプルで0へ収縮**
(w = n/(n+k)、収縮定数kは§5のグリッドで2024のみから選抜):

1. **時計残差 `day_time_resid`**: 各先行レースの勝ち時計 (または上位3頭平均時計) の
   「基準時計」に対する標準化残差の平均 × w。
   基準時計 = 同場・同芝ダ・同距離帯・同馬場状態 (condition) のas-of歴史平均
   (**その開催日より前のデータのみ**で構築。T33のas-of統計の枠組みを再利用)
2. **脚質傾向 `day_pace_bias`**: 先行レースの3着以内馬の4角位置
   (corner_4 / total_horses で正規化) の平均の、歴史baseline (as-of) からの乖離 × w。
   正=前残り、負=差し届き
3. **内外傾向 `day_draw_bias`**: 3着以内馬の枠 (umaban / total_horses 正規化) の
   平均の、歴史baselineからの乖離 × w
4. **不確実性**: n と w を状態値と共に保存し、n=0 の場合は全状態0 (флаг列)

距離帯プーリング (短距離/マイル/中長距離) は芝ダ別のサンプルが薄い場合の
fallbackとして階層化してよいが、構成は事前固定しグリッド探索しない。

## 4. CLへ渡す特徴 (交互作用のみ — 主効果はレース定数で相殺)

状態値はレース内全馬共通のため、単独ではconditional logitで恒等的に無効 (RE §4.5)。
**馬固有特性との交互作用に限定**する:

- `day_pace_bias × horse_pace_type`: 馬の脚質型 (既存pace_fit系のPCI型指標を再利用)
- `day_draw_bias × horse_draw_pos`: 馬の枠 (umaban/total_horses 正規化)
- `day_time_resid × horse_speed_type`: 時計残差 × 馬のスピード型 (tfeat標準化値)
- 各交互作用に対応する availability flag (状態n=0や馬側特徴欠損)

特徴は6列以内に固定する。組合せの探索はしない。

## 5. 実装方式と評価 (T41と同一の隔離パターン・T39プロトコル準拠)

- 新スクリプト `backtest_daystate.py` (T41の `backtest_feature_pack.py` の
  ハーネスを再利用してよい)。**本番 `FEATURES`・本番ファイルは不変**。
  パックOFFで既存出力が決定論SHA一致
- **分割**: 学習2021-23 / 選抜2024 (収縮定数kとL2のみの事前固定小グリッド) /
  2025・2026H1は**historical benchmark** (固定モデルで報告のみ)
- **グリッド (2026-07-18 台帳登録で確定)**: 収縮k ∈ {2, 5, 10} × L2 ∈ {0.3, 1, 3}。
  先行レース数nは0〜11程度のため k はこのレンジ (k=2で当日後半 w≈0.8、k=10で強収縮)。
  これ以外の候補を評価しない
- **構成**: baseline / +X1交互作用 の2構成 (~~T41+X1~~ **T41は2026-07-18に
  不採用となったため落とす**)。計 baseline 3 + X1 9 = **12候補**
- **指標**: 一次 = 勝馬Log Loss (2024)。副 = Brier・top-k捕捉・市場top-kフロア・
  WIN5開催日paired (T39 blocks)。**WIN5用途は§2.1の共通cutoff規約で別集計**
  (後半レースほど先行レース数nが多く状態推定が効く、が本命の仮説)
- レース番号別 (r=1-4 / 5-8 / 9-12) のn分布とcoverage、r別の増分も報告する
- 実行前に上位モデルがT39台帳へ登録する

## 6. テスト

1. **as-ofリーク禁止**: 合成データで、当該レース・同時刻以降・**前日以前**の
   レースが日次状態に影響しないこと (前日データ混入の禁止は明示テスト)
2. WIN5共通cutoff規約 (第1対象−2) の適用と、単レース規約 (r−1) との分離
3. 収縮: n=0で状態0・flag、n増加で w→1 に単調接近
4. 基準時計のas-of性 (当日・未来データがbaselineに入らない)
5. 決定論SHA・本番非回帰
6. `python -m pytest tests/ -q` 全体パス

## 7. 成果物と採否

- `backtest_daystate.py` + テスト + 数値レポート (3構成×3期間、r別増分、
  感度分析、coverage)

  prospective確認で判断。**採用時のライブ配線は別SPEC** (当日先行レース結果の
  リアルタイム取得経路の設計が必要なため)
