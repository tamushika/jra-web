# SPEC T14: fold別コース統計の再集計 (時系列リーク排除)

共通指示: [README.md](README.md) 参照。タスク管理: docs/TASKS.md の T14。
背景理論: docs/prediction-accuracy-improvement-roadmap.md §3.3。

## 背景
バックテストの特徴量・スコアが参照する集計統計 (コース別成績、枠別、騎手別など) の
一部は「全期間 (2021-2025+) の集計」を使っており、2025年を評価するときに2025年自身の
データが統計に混入している (時系列リーク)。統計の元になった db-keiba は過去時点の
スナップショットを提供しないため、**ability.db から「指定日以前のデータのみ」で
同等の統計を再集計する**必要がある。

**Codexは実装と数値報告まで。リークの大きさの解釈・対応の採否は上位モデル。**

## 要求仕様
1. **調査フェーズ (最初に報告に含める)**: backtest_ml.py / backtest_win5.py /
   backtest_criteria.py の特徴量・スコア計算が参照する「期間集計統計」を全て洗い出す。
   候補: コース別複勝率 (course_fit / course_dictionary系)、枠統計 (calculate_waku)、
   騎手点 (j_pts) の元データ、factor_table。それぞれについて
   「集計期間はいつからいつまでか」「評価期間が混入しているか」を表にする。
2. リークしている統計それぞれに対し、`ability.db` の runs から
   `as_of` 日付以前のみで再集計する関数を実装する (新モジュール `fold_stats.py` 推奨)。
   - 集計定義は現行統計と同一にする (定義を変えると効果が混ざって比較できない)。
     現行値との突き合わせ: as_of を現行統計の集計終了日に合わせたとき近い値になることを確認
     (完全一致しない場合は差の理由を報告 — 元データ源の違い等)
   - 小サンプルの扱い (下限件数・全体平均への収縮) は現行の流儀に合わせる
3. バックテスト側に「fold統計モード」を追加 (フラグ例: `--fold-stats`):
   2025年評価では2024-12-31までの統計、2026H1評価では2025-12-31までの統計を使う。
   フラグなしの既存挙動は不変。
4. 比較レポート: 現行 (リークあり) vs fold統計 の 2025 top-kカバレッジ・LogLoss。
   これが「リークの実害の大きさ」の直接測定になる。
5. **本番 (ライブ) 側は変更しない** (ライブは常に「現在までの全データ」で正しい)。

## 受け入れ基準
- 調査表 (統計項目×集計期間×リーク有無) が報告に含まれる
- `--fold-stats` ありなしの比較数値が報告される
- フラグなしの既存出力が不変、既存テストが壊れない

## やらないこと
- ライブ側の統計変更
- 統計定義そのものの改善 (定義変更は効果が混ざる。別タスクで)
