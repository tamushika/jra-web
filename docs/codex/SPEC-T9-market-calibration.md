# SPEC T9: M4-A 市場確率の校正 (バックテスト実装)

共通指示: [README.md](README.md) 参照。タスク管理: docs/TASKS.md の T9。
背景理論: docs/prediction-accuracy-improvement-roadmap.md §4.3 (M4-A)、§3.3 (凍結分割)、§6 (評価設計)。

## 背景
市場確率 (正規化した 1/オッズ) はレース内の順位付けとしては最強のベースラインだが、
確率の**絶対値**には系統的な歪みがある可能性がある (例: 大穴の過大評価 = favorite-longshot bias)。
M4-A は順位を変えずに確率値だけを校正し、Log Loss / Brier を改善する。
改善すれば WIN5 の点数配分と EV 判定の精度に直結する。

**Codex の役割は実装と数値の報告まで。採用するかの判断は上位モデルが行う**
(採用ゲート: roadmap §8)。

## 要求仕様

### 新規スクリプト `backtest_m4a.py`
1. **データ**: ability.db の runs から 2021-01-01〜2026-06-30 を `load_runs` (backtest_ability.py) で
   ロード。各レースについて `parse_final_odds` (backtest_win5.py) で全馬の確定単勝オッズを取得し、
   全馬にオッズがあるレースのみ対象 (8頭以上、平地。既存バックテストの流儀に合わせる)。
2. **市場確率**: `p_i = (1/odds_i) / Σ_j (1/odds_j)` (レース内正規化)。
3. **凍結分割** (絶対に混ぜない):
   - 学習: 2021-2023 (校正マップの推定)
   - 調整: 2024 (セグメント粒度などの選択)
   - 固定テスト: 2025 (最終評価。繰り返し見ない)
   - 追加確認: 2026H1
4. **校正方法**: log(p_market) を入力とする**単調写像** g を学習し、
   `score_i = g(log p_i)` → レース内 softmax/再正規化で校正後確率を得る。
   - 基本実装: sklearn の IsotonicRegression (単調増加制約) または
     ビン別実測勝率 + 全体への収縮 (最小サンプル数を設ける。例: ビンあたり2,000走未満は全体平均へ収縮)
   - **単調性が崩れる実装は禁止** (レース内の人気順位が入れ替わらないこと。
     各レースで校正前後の順位が同一であることを assert で保証する)
5. **セグメント別バリアント** (2024調整データで粒度を選ぶ):
   - V0: 全体一律 (セグメントなし)
   - V1: 芝/ダート別
   - V2: 芝/ダ × 頭数帯 (〜10頭 / 11-14頭 / 15頭〜)
   - V3: 芝/ダ × クラス帯 (新馬・未勝利 / 条件戦 / OP・重賞) — race_class 列から判定
   - 各バリアントを2021-23で学習→2024のLog Lossで比較→最良1つを凍結して2025/2026H1を評価
6. **評価指標** (raw市場確率 vs 校正後、各期間で):
   - レースLog Loss: -(1/N_races) Σ log p̂(勝ち馬)
   - Brier: (1/N_horses) Σ (y_i - p̂_i)² (y=勝ち=1)
   - 信頼性テーブル: 予測確率ビン (例: [0,2%,5%,10%,20%,35%,100%]) ごとの
     予測平均 vs 実勝率 vs 件数 (これが校正の歪みの直接の証拠になる)
7. **出力**:
   - stdout: 期間×手法の指標比較表、選択したバリアントと根拠、信頼性テーブル (校正前後)
   - `api/data_files/common/m4a_calibration.json`: 校正マップ (ビン境界と補正値、
     メタデータ: 学習期間・バリアント・作成日)。**本番コードへの接続はしない**
     (採否判断後に別タスクで行う)
8. **テスト**: tests/test_m4a.py — 合成データで (a) 単調性保証のassert、
   (b) レース内確率の総和=1、(c) 校正マップの保存/読込round-trip、の3件以上

## 受け入れ基準
- `python backtest_m4a.py` が end-to-end で走り、上記の表を出力する
- 全レースで校正前後の順位が同一 (assertで保証。違反があれば即失敗)
- `python -m pytest tests/test_m4a.py -q` パス、既存テストが壊れていない
- 2025固定テストの Log Loss / Brier が raw市場と校正後で両方報告されている
  (改善しているかどうかにかかわらず数値をそのまま報告 — 悪化も貴重な結果)

## やらないこと
- 本番 (jra_win5.py / jra_ev.py / scoring.py) への接続
- MLモデル (conditional logit) との統合・比較 — それは採否判断後の話
- 2025年の数値を見ながらの再調整 (調整は2024のみで完結させる)
