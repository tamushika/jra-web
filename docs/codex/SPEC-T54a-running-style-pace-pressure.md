# SPEC-T54a: 既存データによる事前脚質・展開圧力の診断 (T61優先順3位)

起票: 2026-07-23 (Fable 5)。T61討議合意 (docs/T61-accuracy-roadmap-discussion.md) と
T61a裁定 (T16は市場/CLに明確に劣後・T16b後回し) を踏まえた実行。
**新規データ取得不要** — 既存 `ability.db.runs` の `c4` (2021-25年全行充足・2026年99.5%)
のみで完結する。実装者の担当は数値報告まで。**評価実行は上位モデルがT39台帳へ
登録してから**。採否は上位モデル。

## 1. 仮説

現行の21特徴には `pace_fit` (PCI偏差×予測ペースレベル、速さ/末脚の指標) はあるが、
**「レース中どの位置を走る馬か」という位置取り (脚質) の情報も、「今回のレースは
先行馬が何頭いて展開がどう収縮するか」という展開圧力の情報も一切ない**
(Web表示用の `calculate_kyakushitsu` は記号表示のみでMLに未接続)。
これはpace_fitと直交する情報であり、T61aで示された「既存特徴の使い回しは天井」
という結論の外にある可能性が高い。

## 2. 特徴 (4列固定・組合せ探索なし)

1. `style_pos_asof`: 馬自身の直近4走における「4角通過順位÷その走の頭数」の平均
   (0に近いほど先行、1に近いほど追込)。**as-of** (対象レースより前の走のみ)。
   `api/index.py:calculate_kyakushitsu` と同じ生データ (`c4`, `total_horses`) から、
   記号化せず連続値として算出する
2. `race_pace_pressure_asof`: 同一レース出走全馬の `style_pos_asof` の**レース内平均**
   (先行馬が多いレースほど値が小さくなる=展開が速くなりやすい、という代理指標)。
   同一レースの他馬の値を使うだけで対象馬自身の未来情報は使わないため、
   as-of規約に抵触しない
3. `style_pace_interaction`: `style_pos_asof × race_pace_pressure_asof`
   (「先行馬が多いレースでの先行馬」= 展開負荷が高い、「先行馬が多いレースでの追込馬」
   = 恩恵を受けやすい、を1列で表現)
4. `style_available`: 過去走のc4が2走以上ある馬でのみ1、それ以外は0 (n<2はフォールバックで
   `style_pos_asof=0`・`style_pace_interaction=0`)

計4列。上記以外の派生 (距離帯別分割、surface別分割等) は禁止 (探索空間を広げない)。

## 3. Stage 0: 健全性診断 (副指標・選抜には使わない)

`style_pos_asof` (過去走ベースの予測) と、**当該レースで実現したc4から同じ式で
計算した値**の相関を2024選抜で報告する。相関が高いほど「過去の脚質が今回も
再現される」という前提の健全性を確認できるが、**この相関自体をゲートにしない**
(T18の「表示値とML特徴量の混同」の教訓と同型 — 中間指標は診断用に留め、
採否は最終LogLossのみで行う)。

## 4. 評価 (T39プロトコル準拠)

- **対象は現行CL (21特徴、win5_ml_model.json) への追加のみ**。T16への追加実験は
  今回のスコープ外とする (T61aでT16が市場/CLに明確に劣後すると判明したため、
  投資優先度をCLに絞る。T16側の検証が必要になれば別途起票する)
- T41ハーネス (`backtest_feature_pack.py`) を再利用。本番FEATURES・本番ファイル不変・
  パックOFFで決定論SHA一致
- 分割: 学習2021-23 / 選抜2024 / 2025・2026H1 historical benchmark固定報告
  (21-24 final-refit + 21-23学習版併記)
- グリッド: baseline (現行21特徴) L2{0.3,1,3} + 4列追加 L2{0.3,1,3} = **6候補**
  (収縮kなし・直接計算値のため)
- 一次指標 = 勝馬LogLoss (2024選抜)。副 = Brier・top-k・市場フロア・
  WIN5開催日paired・**距離帯別/脚質帯別の増分内訳** (「先行馬密集レースでの
  追込馬」等、展開圧力が効くと想定される文脈での増分確認)・Stage 0相関の報告

## 5. テスト

1. as-of: 対象レース当日・未来の走が `style_pos_asof` に入らない (合成データ)
2. `race_pace_pressure_asof` が対象馬自身を含む/除くかの一貫性 (レース平均の定義どおり)
3. n<2のフォールバック (0埋め+flag) が正しいこと
4. Stage 0相関の計算が正しいこと (副指標として算出するのみ・選抜に使わないことをコードで保証)
5. パックOFF決定論SHA一致・`python -m pytest tests/ -q` 全体パス
