# SPEC-T59e (P4): 複勝/ワイド/馬連 prospectiveシャドー測定

起票: 2026-07-22 (Fable 5)。T59討議合意 (docs/T59-betting-roadmap-discussion.md) のP4。
前提: T59d (docs/T59d-boards-display-report.md) がsuite再起動 (2026-07-22) で
本番反映済みで、`board_odds_snapshots` (migration v10) への蓄積が次のレース開催
(2026-07-25/26) から自動的に始まる。

**実装者の担当は集計スクリプト・テスト・数値報告まで。採否は上位モデル。**
本SPECは**測定の設計のみ**を今固定する (T39流儀: 数値を見る前にゲートを決める)。
ライブ経路・確率エンジン・通知条件には一切触れない (読み取り専用の集計)。

## 0. 位置づけ

T59d はモデル確率 (複勝・ワイド=T59c受理λ、馬連=λ=1) と実オッズを表示するだけで、
どちらの数値が「良い」かの実運用確認はまだ無い。P4はそれを
**無介入で蓄積し、事前登録した指標で事後に評価する**段階。
**表示は変更しない・推奨も出さない** (P3の規律を継続)。

## 1. 蓄積 (自動・本SPECでは変更しない)

`board_odds_snapshots` に、開催日ごとのT17と同型 (30/10/2分前) で
複勝・ワイド・馬連のモデル確率・公正オッズ・実オッズ・取得時刻が既に貯まる。
本SPECは**この蓄積に触れず**、蓄積が十分たまってから読むだけ。

## 2. 事前登録するゲート・指標 (数値を見る前に固定)

- **蓄積ゲート**: 対象は「30分前スナップショット (`stage=30`) が
  status='ok'で存在するレース」。**開催日数で4開催以上**(T21と同一基準)
  かつ**レース数200以上**に達してから初回集計を行う。未達の間は実行しない
  (途中経過の覗き見はしない — 覗き見た時点で以降の判断が汚染される)
- **確定結果との結合**: `race_results` の確定着順・払戻と
  `race_id + bet_type + combo` で結合。同着・出走取消は
  T59a/T59c と同じ扱い (ブック帯[1.15,1.45]外は集計から除外)
- **一次指標 (券種別・独立)**:
  - 複勝・ワイド: モデル確率 vs 実現結果のBernoulli log loss
    (T59cの一次指標と同一定義、開催日ブロックpaired bootstrap)。
    比較対象は「同時点の実オッズから素朴Harvilleで導出した確率」
    (T59cのbaselineと同一構成)
  - 馬連: 同様にlog loss (モデル=λ=1なので実質baseline=モデル。
    この券種は比較でなく**予測質そのものの継続監視**という位置づけ)
- **副指標**:
  - 校正曲線 (確率10分位ごとの実現率、T59c方式を流用)
  - **CLV (Closing Line Value)**: 各stage (30/10/2分前) のモデル公正オッズが、
    直後の実オッズ変動に対して先読みできているか
    (2分前オッズを「クロージング」とし、30/10分前時点の乖離との相関)
  - 参考ROI: 「公正オッズ>実オッズ (割安)」の組合せを機械的に100円ずつ購入した
    と仮定した場合の回収率 (**表示にも通知にも使わない。事後の参考値のみ**)
- **停止条件**: 事前登録した集計対象・指標・ゲートを、集計後に変更しない
  (結果を見てから間隔[1.15,1.45]を緩めたり母集団を広げたりしない)

## 3. 実装

- 隔離集計スクリプト (新規、例 `backtest_t59e_shadow.py`)。
  `board_odds_snapshots` + `race_results` の結合はread-only
- 蓄積ゲート未達なら「T59e evaluation blocked: N races / M required」で
  fail-closed停止 (T59cのregistration gateと同じ思想)
- 出力: `outputs/t59e_shadow.json` + 開催日別・券種別の内訳表

## 4. テスト

1. 蓄積ゲート (件数不足で停止・十分で実行)
2. 券種別log lossの計算が定義どおり (合成データ)
3. ブック帯除外・同着/取消行の除外
4. CLVの相関計算が符号・定義どおり (合成データ)
5. 参考ROIが表示・通知経路に一切接続されていないことの確認
   (grep等でjra_ev.py/jra_win5.py/index_boards.htmlへの新規結合がないことを検証)
6. `python -m pytest tests/ -q` 全体パス
