ライブ配線はスコープ外** (採用後別SPEC)。

## 1. 目的

JRA公式が公表する馬場の物理計測値 — **含水率 (2018年〜、芝ダ別・ゴール前/4コーナー)**
と**クッション値 (芝、2020年〜)** — を取得し、既存の馬場状態カテゴリ (良/稍/重/不 =
`condition`) を超える**連続値としての増分**を検証する。

- 当日値は**朝9:30頃公表** → その日の全レース (WIN5含む) でas-of利用可能。
  T44 (X1: 当日先行レースからの推定) と違いR1から使える一方、当日中の変化は追えない
- **用途は馬固有特性との交互作用に限定** (RE §4.5の採用条件)。
  単独主効果の広探索・条件細分割はしない

## 2. Stage 0: 取得可能性確認 (最初に実施・失敗なら報告して停止)

1. JRA公式サイトの過去の含水率/クッション値アーカイブ (公表ページ/PDF) の所在と
   **2021-2026年のカバレッジ**を確認する (学習2021-23・選抜2024・評価25/26H1に必要)。
2. 確認は読み取りのみ・最小リクエスト・**1秒スリープ厳守** (JRA公式。netkeiba日次制限
   とは独立だが同じ礼節で)。
3. 報告事項: 取得単位 (開催日×場か)、フォーマット (HTML/PDF)、欠測日、
   計測時刻の記載有無、全期間の推定リクエスト数。
4. **2021年以降に系統的な欠落がある場合はStage 1へ進まず報告** (上位モデルが
   期間短縮の可否を判断する)。

## 3. Stage 1: 収集・保存

- 収集単位: 開催日×場。保存は新規ローカルSQLite or JSON
  (`api/data_files/common/` 配下ではなくリポジトリ直下の未追跡ファイル。
  本番data_filesへは採用まで置かない):
  `date, venue, turf_moisture_goal, turf_moisture_4c, dirt_moisture_goal,
  dirt_moisture_4c, cushion, published_at (記載があれば), source_url, fetched_at`
- 概算規模: 開催日 ~590日 (2021-2026H1) × 1-2リクエスト/日 → 数百〜千数百リクエスト。
  連続失敗10回で自動停止 (既存スクレイパーの作法)。日をまたぐ分割実行可の再開可能設計
- 値は公表どおりのrawを保存 (丸め・補間をしない)。欠測はNULL

## 4. 特徴 (交互作用のみ・6列以内固定)

レース定数のためconditional logitでは主効果は恒等無効 (T44 §4と同じ理屈)。
以下に固定し、組合せ探索をしない:

- `moisture_x_wet_match`: 当該surface側の含水率 (ゴール前) × 馬の道悪適性
  (既存 `wet_match` フラグの実数化に既存定義を再利用)
- `moisture_x_pace_type`: 含水率 × 馬の脚質型 (pace_fit系PCI型指標)
- `cushion_x_speed_type`: クッション値 × 馬のスピード型 (tfeat標準化値)。芝のみ・
  ダートは0+flag
- 各 availability flag (公表値欠測・2020年以前のクッション値等)
- 含水率は**同場同surfaceの歴史as-of平均からの偏差**に標準化してから交互作用に使う
  (絶対値は場・季節でレンジが違うため。標準化統計は当該開催日より前のデータのみ)

## 6. テスト

1. as-of: 標準化統計に当日・未来が入らない (合成データ)
2. 欠測日・クッション値非公表期間のflagとフォールバック
3. 芝レースにダート含水率を使わない (surface対応の正しさ)
4. パックOFF決定論SHA・`python -m pytest tests/ -q` 全体パス
5. パーサ: 実ページ/PDFのfixtureで数値抽出の正確性 (少なくとも2時点)
