# SPEC T13: レース内相対特徴量 (T33の後、T11と並行可)

共通指示: [README.md](README.md) 参照。タスク管理: docs/TASKS.md の T13。
背景理論: roadmap §4.4。conditional logit はレース内比較のモデルなので、
絶対値特徴に加えてレース内相対値を与える価値が高い、という仮説の検証。

**Codexは実装と数値報告まで。採否は上位モデル。**

## 要求仕様
1. `backtest_ml.py` の build_dataset に相対特徴量を追加する (`--relative` フラグで有効化、
   既定はオフで既存挙動不変):
   - tfeat_rank: タイム指数 (tfeat) のレース内順位 (1=最良、頭数で正規化)
   - tfeat_gap_med: tfeat − レース内中央値
   - tfeat_gap_best: tfeat − レース内最大値
   - j_pts_dev / f_pts_dev / sire_pts_dev: 各点のレース内偏差 (値 − レース平均)
   - kinryo_dev: 斤量のレース内偏差
   - n_prior_dev: 過去走数のレース内偏差 (キャリア差)
   ※ 欠損は「レース平均=0扱い」で偏差0に落とす (学習と評価で同一処理)
2. **ライブ側との一致可能性を必ず確認**: これらはライブでも analyze_race_url が
   全馬分を持つ情報から計算可能なはず。ライブ実装は本タスクではやらないが、
   「ライブで同一に計算できない特徴」が混ざる場合は除外して報告 (§3.2の教訓)
3. 分割: 学習2021-23 / 調整2024 (特徴選択が必要なら) / 固定テスト2025 / 確認2026H1。
   統計ソースはT33経路 (未完なら現行統計で実行し明記)
4. 報告: ベース (現行20+ln_odds) vs ベース+相対特徴 の top-k/LogLoss/Brier ×2期間、
   係数表 (どの相対特徴が効いたか)、人気ベースライン併記
5. M3構造 (T11) が既にあれば「M3+相対特徴」も1行追加 (安ければ)

## 受け入れ基準
- フラグなしの既存挙動・出力が不変
- 比較表×2期間 + 係数表が報告される
- --write 禁止。全テストパス

## やらないこと
- ライブ側への実装 (採否後の別タスク)
- 特徴量の無制限な追加 (上記リストで検証。追加候補は報告に書くだけ)
