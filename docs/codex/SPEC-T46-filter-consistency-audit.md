# SPEC T46: 学習/ライブ/評価のフィルタ一貫性監査 (E3)

背景: [RE-accuracy-ideas-20260717.md](RE-accuracy-ideas-20260717.md) §8/§9 (E3=最優先)。
起票: 2026-07-18 上位モデル。

**READ-ONLYの調査タスク。コード変更禁止。** 成果物はマトリクス文書のみで、
発見された不一致の是正は上位モデルが個別に起票する。

## 1. 目的

「同一集団比較」(検証の作法 §2) の前提である母集団フィルタが、
①学習 (backtest_ml build_dataset 系) ②ライブ (analyze_race_url / scoring / jra_ev)
③評価 (backtest_win5 / backtest_ev / eval系・T4市場ベースライン) の3経路で
一貫しているかを網羅的に照合する。

## 2. 監査対象のフィルタ軸 (最低限。コードを読んで軸自体の抜けも追加すること)

1. **開催の範囲**: 地方交流レースの扱い (ability.db に含まれるか、学習で
   除外されるか、ライブで解析対象になるか)
2. **障害レース**: track_type での除外の有無と経路間差
3. **出走状態**: 取消・除外・中止馬 (rank欠損/マーカー行) の各経路での扱い
4. **履歴なし馬**: n_prior=0 / 特徴構築不能馬の除外規則 (build_datasetの
   除外と、ライブでのml_score=None の対応関係)
5. **頭数条件**: WIN5評価の8頭以上フィルタが評価専用であることの確認
   (学習・ライブに漏れていないか)
6. **オッズ条件**: 「オッズあり」フィルタの定義差 (odds>1.0 / _valid_win_odds /
   発売前) — T40で判明した判定式の並存を含む
7. **期間・年**: 各スクリプトのdate範囲定数のハードコード差
8. **レース番号**: WIN5評価の9R以降フィルタの適用箇所

## 3. 方法

- 該当コードを grep + 精読し、**フィルタ×経路のマトリクス** (行=フィルタ軸、
  列=学習/ライブ/評価、セル=規則と `file:line`) を作成
- 規則が同一に見えても定義が微妙に違うもの (例: odds>1.0 vs 1.0<odds<999) は
  「差分あり」として明記
- 可能なものは実データで件数確認 (例: ability.db 2025年の地方交流・障害の行数と、
  build_dataset通過後の行数)。ability.dbへの書き込みは禁止
- 進行中実験 (T41等) のファイルには触れない
