# SPEC-T62: as-ofレースレベル相対信頼度スコア (勝負レース選定・歴史足切り段階)

起票: 2026-07-24 (Fable 5)。T62討議合意 (docs/T62-race-selection-discussion.md) の実行第1弾。
**本SPECのスコープは「歴史データでの足切り評価」まで。表示接続・シャドー測定・採否は対象外**
(歴史ゲート通過時のみ、別SPECで表示専用接続を起票する)。

**実装者の担当は実装・テスト・数値報告まで。採否・ゲート通過判断は上位モデル。
T39台帳への事前登録 (評価実行前) を必須とする。実装前に、本SPECの入力列定義に
as-of計算不能なもの・欠損時処理が未定義なもの・rolling-origin境界を破るものがないかを
監査し、あれば実装前に差し戻すこと (討議合意の分担)。**

## 0. 目的と位置づけ

グローバル平均で市場同等〜微劣後のモデル (senior-model-handoff.md §4) を前提に、
「**どのレースでモデルを相対的に信じられるか**」をas-of判定するレースレベルスコアを構築する。
これは特徴追加による精度向上 (T61路線、全滅) とは別軸であり、購入推奨ではない。

## 1. モデル形式 (討議合意・変更禁止)

- **ridge回帰** (L2正則化線形回帰)。目的変数は連続値
  `y_r = log(p_model(勝馬)) - log(p_market(勝馬))` (レースrの実現勝馬に対する両確率の対数比。
  正値=モデル優位)
- 候補は **L2 ∈ {0.3, 1.0, 3.0} の3つのみ**。特徴選択・形式変更・選定率変更の探索禁止
- 選定率は **20%一点を一次** (予測y_r上位20%を「勝負レース」とする)。10%/30%と選定率曲線は
  診断限定 (採否にも選抜にも使わない)

## 2. 入力列 (固定11列・as-of計算可能なもののみ)

すべて**発走前に計算可能**な値であること。モデル確率はbase CL (現行21特徴) の出力、
市場確率は正規化オッズ逆数。

| # | 群 | 列 | 定義 |
|---|---|---|---|
| 1 | 乖離 | `js_divergence` | モデル確率ベクトル vs 市場確率ベクトルのJensen-Shannon divergence |
| 2 | 乖離 | `top1_disagree` | モデルtop1と市場top1が異なるか (0/1) |
| 3 | 乖離 | `rank_corr` | 両確率ベクトルのSpearman順位相関 |
| 4 | 確信度 | `model_entropy` | モデル確率の正規化エントロピー (log(頭数)で割る) |
| 5 | 確信度 | `market_entropy` | 市場確率の正規化エントロピー |
| 6 | 確信度 | `market_top1_margin` | 市場top1確率 − top2確率 |
| 7 | availability | `hist_coverage` | 出走馬のうち直近4走の有効履歴が2走以上ある馬の割合 (T54dのsectional_availableと同型の定義でよいが、`runs`ベースの走歴で可) |
| 8 | オッズ品質 | `odds_takeout` | 1/オッズ合計の超過分 (控除率の実測代理) |
| 9 | 頭数 | `field_size` | 出走頭数 (連続値1列のみ、区分化しない) |
| 10 | 種別 | `is_maiden` | 新馬・未勝利か (0/1) |
| 11 | 種別 | `class_level` | クラスの序数 (新馬/未勝利=0、1勝=1、2勝=2、3勝=3、OP/重賞=4。既存の判定資産があれば流用) |

- 障害レースは母集団から除外 (既存WIN5評価母集団の慣行に合わせ、9R以降・8頭以上・
  オッズありの同一母集団で全評価を行う — baseモデルの評価と同じ集団)
- 欠損時処理: 列ごとに「計算不能ならレースを母集団から除外」ではなく**0埋め+欠損flagは作らない**
  (列追加は多重性を増やすため)。ただし市場オッズ欠損レースは母集団から除外 (y_rが定義できない)

## 3. rolling-origin (討議合意・変更禁止)

メタ学習データのbase-model予測は**厳密時系列のOOS予測**でなければならない:

1. base CL (現行21特徴・現行学習手順) を**2021年のみ**で学習 → 2022年の全対象レースを予測
2. base CLを**2021-2022**で学習 → 2023年を予測
3. 上記OOS予測から y_r と入力列を構成し、**2022-2023の2年分**でridgeを学習
4. **2024年**: base CLは標準の2021-2023学習版を使用。ridgeのL2選択と20%選定の一次評価を行う
5. 選択後、**係数・前処理 (標準化パラメータ)・選定閾値をfreeze** (freeze manifestに記録)
6. **2025/2026H1**: 反証専用。freezeされたスコアで選定し、結果を報告するのみ。
   いかなる再調整も禁止

leave-one-year-out (2021年を2022-23学習モデルで予測する等) は時系列を破るため**禁止**。

## 4. 評価 (T39事前登録・評価実行前に登録)

- **一次指標**: 2024選定20%集合における「モデル勝馬LogLoss − 市場勝馬LogLoss」の
  開催日paired block bootstrap (2000回)。帰無仮説「差≥0」の**片側検定**
- 3候補 (L2×3) の多重比較補正を適用 (Bonferroniで可)
- **必須報告** (各期間: 2024/2025/2026H1):
  - 選定集合と**未選定集合の両方**の指標 (単なる全体改善の切り出しでないことの確認)
  - 市場top-kフロア (選定集合内で市場人気top-kとの捕捉率差)
  - 人気帯分解 (1-3/4-8/9+、選定・未選定両方)
  - 選定率曲線 (10-30%、診断のみ)
- **足切り判定**: 2024で有意 (補正後片側p<0.05) かつ2025・2026H1の両方で
  同方向 (選定集合の差が負=モデル優位) であること。**通過しても採用にはならない** —
  獲得するのは表示専用+シャドー測定 (別SPEC) への進出権のみ
- `ability.db` 封印SHA-256: `bbee39cc91d7c42b9df6f67bd58875514c5eda7977adb165e330c11ab990860a`

## 5. 既知の限界 (台帳のfeatures欄に明記)

- 歴史評価の市場確率は**確定オッズ**由来。prospective運用時はcutoffスナップショット由来になり
  分布が異なる。この差は歴史段階では除去できず、シャドー段階で実測する (T21と同じ問題意識)
- 2025/2026H1は過去の多数の裁定で再利用済みのhistorical benchmarkであり、
  通過は「prospective検証に進む価値がある」以上の意味を持たない

## 6. 制約

- 本番 `combo_probs.py`・`win5_ml_model.json`・通知関数・表示UIには一切接続しない
  (隔離ハーネス `backtest_t62_race_selection.py` として新規実装)
- `runs`・`runner_corners`・`race_laps`・オッズ関連テーブルは読み取り専用
- 通知条件 (LINE=5分前×EV≥1.3) は不変

## 7. テスト

1. as-ofガード: 入力列に対象レース自身の結果 (勝馬・確定着順・払戻) が混入しないことの回帰テスト
2. rolling-origin境界: 2022年予測に2022年以降のデータが使われないことのテスト
3. y_rの定義: 実現勝馬に対する対数比が正しく計算されることの単体テスト (dead-heat時は
   既存慣行に合わせ勝馬平均)
4. T39登録前のfail-closedゲート (T54dと同型)
5. freeze manifest: 係数・前処理・閾値のSHA-256が再現されることのテスト
6. `python -m pytest tests/ -q` 全体パス
