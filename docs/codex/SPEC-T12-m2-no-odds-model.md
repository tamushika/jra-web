# SPEC T12: M2 オッズなし基礎能力モデル

共通指示: [README.md](README.md) 参照。タスク管理: docs/TASKS.md の T12。
背景理論: docs/prediction-accuracy-improvement-roadmap.md §4.1 (M2の位置づけ)。

## 背景
現行WIN5モデル (conditional logit、21特徴量) は `ln_odds` が支配的 (係数−1.44)。
「市場情報を一切使わないとき、独自特徴だけでどこまで予測できるか」を測るのがM2。
これは後続のM4-B (市場順位とM2能力順位の差を補正特徴に使う) の部品にもなる。
**Codexは実装と数値報告まで。採否・解釈は上位モデル。**

## 要求仕様
1. `backtest_ml.py` に `--no-market` フラグを追加: 特徴量から `ln_odds` を除外して
   同じ conditional logit を学習・評価する (他の20特徴量はそのまま)。
   - 特徴量リストの持ち方を確認し、除外がモデルJSONの出力に混ざらないようにする
     (`--write` との併用は禁止 — フラグ同時指定ならエラーにする)
2. 分割は既存ハーネスの流儀 (学習2021-24 / テスト2025) を変えない。
   検証出力には既存の人気順ベースライン行 (T4で追加済み) が同一集団で並ぶこと
3. 報告する指標 (2025テスト、可能なら2026H1も):
   - top-k勝ち馬カバレッジ (k=1..4): M0(人気) / 現行(オッズ込み) / M2(オッズなし)
   - レースLogLoss と Brier (同3者。市場確率はレース内正規化 1/odds)
   - M2順位と市場順位の相関 (スピアマン、レース内平均) — M4-Bの効きの見込みを測る材料
4. 検証: `python backtest_ml.py --no-market` が end-to-end で走る。
   既存の `python backtest_ml.py` (フラグなし) の出力が変わらないことを確認
5. テスト: 既存テストが壊れないこと (`python -m pytest tests/ -q`)

## 受け入れ基準
- フラグなし実行の挙動・出力が完全に不変
- 上記指標が全て数値で報告される (M2が弱くてもそのまま報告 — それ自体が貴重な結果)
- `--no-market --write` はエラーで拒否される

## やらないこと
- M2モデルの本番保存・接続
- 特徴量の追加・削除 (ln_odds除外のみ。相対特徴量はT13で別途)
