# SPEC T16: Web用複勝確率モデル (独立・いつでも着手可)

共通指示: [README.md](README.md) 参照。タスク管理: docs/TASKS.md の T16。
背景理論: roadmap §4.6。現行Webスコアは手動加点の合計で、複勝率との単調性はあるが
校正された確率ではない。オッズ不使用の「3着内確率モデル」を作り、現行スコアと
シャドー比較する。市場劣後が判明した単勝系と違い、Web版は市場から独立した
妙味探し用途なので独立に価値がある。

**Codexは実装と数値報告まで。採否は上位モデル。**

## 要求仕様
1. 新規 `backtest_place_model.py`:
   - 目的変数: rank <= 3 (複勝圏内。7頭以下レースは2着内 — JRAの複勝ルールに合わせる)
   - 特徴量: NO_MARKET_FEATURES (ln_odds抜き20特徴、backtest_ml.build_dataset を再利用)
   - モデル: ロジスティック回帰 (L2、per-horse独立。レース内softmaxは使わない —
     複勝は独立事象に近い) + isotonic か Platt で確率校正 (校正は2024データで)
   - 統計ソースはT33経路 (未完なら現行統計で実行し明記)
2. 分割: 学習2021-23 / 校正・調整2024 / 固定テスト2025 / 確認2026H1
3. 比較対象: 現行Webスコア (backtest_score系の既存ハーネスでスコア付与) を
   同一レース集団で並べる
4. 報告 (×2期間):
   - スコア/確率の上位1・3・5頭の複勝捕捉率 (現行 vs 新モデル)
   - Brier、確率帯別の予測複勝率 vs 実複勝率 (信頼性テーブル)
   - 人気帯別 (1-3番人気/4-8/9-) の複勝率とオッズなし複勝回収率
5. 出力: モデルは `web_place_model.json` としてスクラッチnot本番ディレクトリに保存
   (本番接続・画面表示はしない — 採否後にシャドー列として別タスクで表示)
6. テスト: 校正のround-trip、7頭以下レースの目的変数切替、の2件以上

## 受け入れ基準
- 現行Webスコアとの同一集団比較表×2期間
- 確率が校正されている証拠 (信頼性テーブル)
- 本番ファイル無変更。全テストパス

## やらないこと
- オッズ・人気を特徴に入れる (市場独立が価値。混ぜたら別物)
- 画面への表示 (採否後)
