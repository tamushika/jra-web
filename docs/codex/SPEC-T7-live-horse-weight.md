# SPEC T7: 当日馬体重のライブ取得

共通指示: [README.md](README.md) 参照。タスク管理: docs/TASKS.md の T7。依存: T5 (検証に使う)。

## 背景
学習時の特徴量 `weight` (馬体重) は当該レースの実測値だが、ライブ予測時は当日値が
まだ無いため前走値で代用している。当日馬体重はJRA公式で発走の約1時間前に公表されるため、
発走が近いタイミングの予測 (EV監視の30分前以降のステージ、WIN5の締切前再計算) では
当日値を使える。

## 要求仕様
1. 当日馬体重の取得元を調査して決める。候補:
   - JRA公式の出馬表/オッズページ (jra_ev.py が既に取得しているページに馬体重が
     含まれていないか最初に確認 — 含まれていれば新規スクレイパー不要で最善)
   - netkeiba の出馬表 (race.netkeiba.com)。取得できる時間帯に注意
2. 取得した当日馬体重 (増減も取れるなら併せて) をライブ特徴量生成に渡す:
   - 当日値があれば当日値、なければ従来どおり前走値 (フォールバックを明示するフラグを持つ)
3. EV監視 (jra_ev.py) では30分前以降の再取得時に反映されれば十分。
   レースごとに1回取得できればよく、ポーリング毎に取り直さない。
4. WIN5アプリの「締切前再計算」経路にも同じ値が乗るようにする。

## 受け入れ基準
- 過去の完了レースで検証: 当日馬体重の取得値が ability.db の runs.weight と一致する
  (10レース程度サンプルで100%一致。公表前の時間帯はフォールバックが働くこと)
- T5 parity テストの weight 項目が「発走1時間以内なら一致」になる (テストの許容リスト更新)
- 通知条件・通知頻度に変化がない (取得失敗時も従来動作にフォールバック)

## やらないこと
- モデル再学習
- パドック情報等の他の当日情報の追加
