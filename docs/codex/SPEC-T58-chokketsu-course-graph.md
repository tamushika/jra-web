## 0. 何が価値か / 何が危険か (上位モデルの事前評価)

- **価値**: 第5章 (p136〜巻末、約86ページ) に全10場×全コース×クラス帯
  (古馬重賞OP / 古馬条件・未勝利 / 2-3歳限定) の**直結コース対応表 (S/Aランク)** =
  「どのコースの好走実績が今回コースに転移するか」の有向グラフが載っている。
  実物確認済み (例: p140 東京芝2400m — 古馬OPのSランク直結: 東京芝2400/東京芝2000/
  阪神芝2200/中京芝2000/東京芝1800/阪神芝2400)。当システムには**コース間の実績転移の
  事前構造が無い** (tfeat等はコース無差別集計) ため、新しい情報軸になり得る
- **危険 (必ず登録に明記)**: 本書の表は「26年データ」= **我々の評価期間 (2024/2025/26H1)
  を含むデータで著者が選定したもの**。これを2021-25の凍結分割で検証すると
  look-aheadの楽観を含む。したがって:
  - historical検証は**反証フィルタ**として使う (リーク込みでも効かなければ強い負の結果)
  - historicalで通っても**採用はprospective確認 (T39) を必須ゲート**とする
- 規律は書籍共通ポリシー (SPEC-T57 §0) に従う: 数値は仮説・離散ルール一括導入禁止・
  転写/抽出データはローカルのみ (コミットするのは検証コードと集計結果)

## 1. Stage 0: 対応表の構造化抽出

1. 対象は**第5章のみ** (約86ページ)。第4章のポイント表 (著者の配点) は抽出しない
2. OCRは**ローカルollama (qwen系vision)**。出力は1ページ=1レコードのJSON:
   `{target_course: "東京芝2400", class_group: "古馬重賞OP"|"古馬条件未勝利"|"2-3歳限定",
     s_rank: [コース名...], a_rank: [コース名...], page: n}`
3. コース名の正規化辞書 (場名10+芝ダ+距離+内外) を固定し、**未知語彙は失敗として
   報告** (黙って捨てない)
4. 品質確認: 無作為10ページを目視突き合わせ (誤転写は特徴を壊す)。
   カバレッジ表 (場×コース×クラス帯の欠け) を報告
5. 成果物: ローカル `data/t58/chokketsu_graph.json` (gitignore) + カバレッジ報告。
   スクレイプ・外部送信・本番変更なし

## 2. Stage 1: 特徴量検証 (Stage 0通過後・上位モデルが台帳登録してから)

- 特徴 (6列固定・組合せ探索なし):
  1. `bp_connect_s`: 過去走 (as-of) のうち今回コースのSランク直結コースでの
     最良標準化パフォーマンス (tfeat系の既存標準化を再利用)
  2. `bp_connect_a`: 同Aランク
  3. `bp_nonconnect`: 直結外コースでの最良好走 (人気の源泉が転移しない、のfade側仮説)
  4. `bp_same_course`: 今回と同一コースでの最良 (直結の自明ケースを分離)
  5. `bp_connect_available` / `bp_nonconnect_available`: flag 2列
- クラス帯は書籍の3分類をそのまま使う。as-ofは過去走のみ・凍結分割は通常どおり
- グリッド: baseline L2{0.3,1,3} + 特徴 L2{0.3,1,3} = 6候補 (収縮kなし・直接観測)
- 一次指標 = 勝馬LogLoss (2024選抜)。副 = 市場フロア・WIN5開催日paired・
  人気帯別増分 (穴側で効く、が本書の主張) ・クラス帯別内訳
- **台帳登録に必ず含める**: 書籍データのlook-ahead警告と「採用にはprospective確認必須」
