# SPEC-T59d (P3): 複勝/ワイド/馬連 買い目表示 (公正オッズ・実オッズ・乖離、表示専用)

起票: 2026-07-22 (Fable 5)。T59討議合意 (docs/T59-betting-roadmap-discussion.md) の
P3。前提として T59a (歴史オッズ被覆PASS)・T59b (JRA公式主系でGo)・T59c
(複勝/ワイド=段階λ校正を受理、馬連=不採用で素朴Harville維持) が確定済み。

**実装者の担当は実装・テスト・数値/画面確認まで。採否・コミット・デプロイは上位モデル。**
⚠️ ライブ経路 (取得ループ・Web/監視UI) を触るため、**実装は平日**・
**切替 (suite再起動) はレースの無い平日** (T38/T47/T56の次バッチでよい)。

## 0. 絶対規律 (最重要・全体に優先)

1. **表示専用・推奨なし**: 「買い」「推奨」「◎」等の購入誘導表現を一切出さない。
   出すのは「モデル確率」「公正オッズ (1/確率)」「実オッズ」「乖離 (公正/実オッズ比)」
   「オッズ取得時刻」のみ。**テストで推奨文言の不在を機械的に保証する** (T56の
   `?date=`応答不変テストと同じ精神: 出力全文字列を走査し禁止語彙リストに
   一致しないことをassert)
2. **通知条件・EV通知は一切変更しない** (`_send_line`/`_send_discord`/
   `refresh_and_alert` はAST比較で不変性を確認。本SPECは新規の表示・ログ経路のみ追加)
3. **本番の勝率エンジン (CL, win5_ml_model.json) は変更しない**。本SPECの確率は
   **市場勝率 (単勝オッズ逆数) を土台**にした新規の独立モジュールで導出する
   (T59討議合意: CLはシャドー降格)
4. **既存 `api/combo_probs.py` (λ=0.7ワイド、運用停止済み) には触れない**。
   本SPECは新規ファイルで実装し、旧モジュールとの混同を避ける
5. これはP4 (prospectiveシャドー) の前段。**本SPECでは購入・EV通知の判断材料には
   一切ならない** (表示ページを見てユーザーが手動で判断する材料に留める)

## 1. 確率導出モジュール (新規・隔離)

- 入力: レースの単勝市場確率 (オッズ逆数正規化、T59a/T59c方式・
  ブック帯[1.15,1.45]外は「確率算出不可」を明示表示)
- 複勝・ワイド: T59c受理値 **λ2=0.830185 / λ3=0.720886** で段階割引Harville。
  複勝は7頭以下で2着内ルール (T59c §2-3と同一)
- 馬連: **λ=1 (素朴Harville、T59c不採用の裁定どおり)**
- 三連複: 本SPECの対象外 (表示しない。T59c登録時も参考のみ)
- 数学的不変条件のassertをそのまま流用可 (T59cテストの構成を参考にしてよい)

## 2. 実オッズ取得 (T59b合意の実装化)

- **主系: JRA公式**。`poc_t59b_odds_boards.py` のCNAME取得パターンを土台に
  本実装へ格上げする (複勝・ワイド・馬連の3券種のみ。枠連・三連複は取得しない)
- **netkeibaは使わない** (T59b裁定: 照合専用に留め、本番依存にしない。
  本SPECは表示専用なので照合の必要自体がない)
- **既存30/10/2分前スナップショットループ (`jra_ev.py` の `_SNAPSHOT_STAGES`) への
  相乗りを第一候補とする** (T17と同型の取得タイミングで、追加リクエストの
  発生源を一本化する)。相乗りが構造的に難しい場合のみ独立ループを新設してよいが、
  その場合もnetkeiba日次制限とは無関係な情報源なので他タスクとの調整は不要
- 取得失敗時は前回値を流用せず「取得失敗」を明示 (T59b報告の停止条件と同じ思想)
- 保存: 新規テーブル (例 `board_odds_snapshots`) に
  `date, place, r, bet_type, combo, odds, requested_at, received_at, source`
  を保存する。**これはP4のprospective集計がそのまま消費できるスキーマにする**
  (P4着手時にスキーマ変更を要求しないこと)

## 3. 表示 (Web/監視UIへの追加)

- 表示先はsuite統合後のperf/win5/ev画面のいずれか、実装者が最も自然な箇所を選んでよい
  (例: WIN5詳細画面に複勝/ワイド/馬連タブを追加)
- 各組合せ行: モデル確率・公正オッズ・実オッズ・乖離・オッズ取得時刻。
  乖離が大きい行の強調表示は色分け程度に留め、**「買い」に類する文言は禁止**
- ブック帯外・オッズ未取得のレースは「表示不可」を明示 (欠測を隠さない)
- 外部ライブラリ追加なし (T56と同じ手書きHTML/JSの流儀を踏襲)

## 4. テスト

1. 確率モジュール: λ校正値の適用が数値的に正しい (T59cの既知ケースと一致)・
   複勝7頭ルール・確率総和の不変条件
2. **禁止語彙テスト**: 生成されるHTML/JSON全体に「買い」「推奨」「◎」「⭐」等の
   購入誘導語彙が一切含まれないことをassert (固定リストを用意)
3. オッズ取得: JRA公式fixtureで正常系・取得失敗時の「取得失敗」表示・
   ブック帯外レースの「表示不可」表示
4. 通知関数3つのAST不変性確認
5. 本番combo_probs.py / win5_ml_model.json 無変更の確認 (diffゼロを機械テスト化してもよい)
6. `python -m pytest tests/ -q` 全体パス
