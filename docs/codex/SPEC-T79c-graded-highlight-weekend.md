# SPEC-T79c: 重賞データページの好成績セル強調と、週末重賞の金曜先行表示

起票: 2026-09-25 (Fable 5.1)。ユーザー要望: 「重賞データは、特別勝率がいいデータを色を付けて分かりやすくしたい」「G1 などのデータは、早くに枠順や出走馬が解禁されているので金曜日には見られるようにしたい」。T79/T79b の追補。

## 0. 調査済みの事実
- 現行の `/graded/api/this_week` は `jra_ev.STATE["races"]` (オッズ監視の解析済み出馬表 = 当日または直近 1 開催日) だけを見る。金曜に「🏇 解析開始」を押すと土曜分だけが解析され、日曜の G1 は出ない。
- JRA の出馬表 (枠順確定) は土曜分が木曜、日曜分が金曜に公開される (G1 は木曜)。
- `https://www.jra.go.jp/keiba/thisweek/` (今週の注目レース) には週末の主要重賞の出馬表リンク (`/JRADB/accessD.html?CNAME=pw01dde01<場2桁><年4桁><回2桁><日2桁><R2桁><YYYYMMDD>/<hex>`) が土日両方分載る (2026-09-25 時点: 9/26 阪神 11R, 9/27 中山 11R の 2 件。リンクテキストは空 = 画像)。ただし注目レースに含まれない G3 は載らないことがある。
- 出馬表ページから `api/index.py:build_matrix_data(soup)` で週末の全「場×日」(例 `9/26(土) 4回中山7日`) と各レースの URL が取れる (`fetch_races_for_venue` → `{"text","url","races":[{"r","url"}]}`。レース名は含まない)。レース名は各出馬表ページの `class="race_name"` (index.py 1299 行付近) から読める。
- 出走馬の属性 (T79b の pick) は `index.analyze_race_url(url)` で取れ、枠順未確定の段階では `w_num`/馬番が無い。

## 1. 好成績セルの強調 (`index_graded.html`)
1. 傾向表 (人気/枠/脚質/性齢/所属/前走/前走着順/父/騎手/馬体重/間隔) の各行に、**全体との比** で色を付ける。全体値は履歴 API の `overall_fuku_rate` と全体勝率 (= Σ1着/Σ出走、API に `overall_win_rate` を追加) を使う。
   - `n ≥ 8` かつ 複勝率比 ≥ 1.5 または 勝率比 ≥ 2.0 → **強** (背景 緑 rgba(78,214,176,.22)、数値太字、行頭に ★)。
   - `n ≥ 8` かつ 複勝率比 ≥ 1.2 または 勝率比 ≥ 1.5 → **中** (背景 緑 rgba(78,214,176,.10))。
   - `n ≥ 8` かつ 複勝率比 ≤ 0.6 → **弱** (文字色 muted、背景 赤 rgba(255,107,107,.08))。
   - `n < 8` は色を付けず「n 少」を薄字で表示 (現状の最大行の薄い強調は廃止)。
2. 単回収・複回収が 120% 以上のセルは数値を金色 (#ffd54f) にする (回収は n ≥ 8 のときのみ)。
3. 表の上に凡例 (★ 強: 全体の1.5倍以上 / 中: 1.2倍以上 / 赤: 0.6倍以下、n≥8) を 1 行で出す。
4. T79b の照合表 (出走馬) では、hits チップのうち「強」に該当する区分を ★ 付きで先頭に並べる。

## 2. 週末重賞の先行表示 (`jra_graded.py` + `index_graded.html`)
1. 新規 `GET /graded/api/weekend_graded?refresh=0|1`: 今週末 (次の土・日、月曜開催があればそれも) の重賞候補を返す。手順:
   a. `jra_ev.find_entry_url()` → 出馬表ページ → `build_matrix_data` で「場×日」と全レース URL を列挙 (今日以降の日付のみ)。
   b. 各「場×日」の **9R〜12R** のみ出馬表ページを取得し (`requests`、0.5 秒間隔、タイムアウト 10 秒)、`race_name` と発走時刻・距離・芝ダ・頭数・枠順確定の有無 (馬番/枠が揃っているか) を読む。ページ取得は最大 3 場 × 3 日 × 4R = 36 件。
   c. `graded_names.match_key` で重賞に該当するものだけを `[{date, venue, race_num, race_name, url, key, display_name, grade_latest, start_time, draw_fixed: bool, source: "jra_card"}]` で返す。「今週の注目レース」ページのリンク (a に無ければ) も候補に加える (dedupe は url)。
   d. 結果はロギング DB の新テーブル `weekend_graded_cards` (url PK, date, venue, race_num, race_name, key, draw_fixed, fetched_at) に保存し、**6 時間以内の取得済みなら再取得しない** (`refresh=1` で強制)。木・金の朝 (解析なし) にも使えるよう、`jra_suite` 起動時とタブシェルの「🏇 解析開始」完了時にバックグラウンドで 1 回更新 (失敗は警告ログのみ)。
2. `this_week` の統合: 既存の `this_week` (EV 解析分、`source:"ev_state"`) と `weekend_graded` を **url で dedupe して結合**し、日付・発走順に並べる。応答に `source` と `draw_fixed` を含める。
3. UI: 「今週の重賞」チップを日付ごとにグループ表示 (`9/26(土)` / `9/27(日)`)。`draw_fixed=false` のチップには「枠順未確定」バッジ。手動更新ボタン「週末の重賞を再取得」(refresh=1)。チップを選んだときの照合 (T79b `api/pick`) は URL があるので従来どおり動く。枠順未確定なら照合表の枠・馬番列を「—」にし、見出しに「枠順確定後に再取得」と表示。
4. **本番 Web への影響なし** (jra_graded は統合版のみ)。JRA へのアクセスは上記の頻度制限内。

## 3. テスト (`tests/test_t79c_graded_highlight_weekend.py`)
- 強調判定の純関数 (比率・n 閾値・境界)、`overall_win_rate` が API に含まれる。
- 出馬表 HTML fixture (レース名・発走・枠順あり/なし) からのメタ抽出、`match_key` による重賞判定 (非重賞 `ながつきステークス` は除外)、CNAME から日付の抽出、dedupe と並び順、6 時間キャッシュの再取得規則、`weekend_graded_cards` の保存。
- `this_week` の統合 (EV 分と週末分の両方があるとき url 重複が 1 件になる)。
- 既存 `tests/test_t79_graded.py` `tests/test_t79b_graded_pick.py` が通る。通知関数 AST 不変。

## 4. 受け入れ (手動・ユーザー)
1. 金曜に重賞データタブを開くと、土曜・日曜の重賞がチップで並び、日曜 G1 の過去傾向と出走馬の照合が見られる (枠順確定後は枠も反映)。
2. 傾向表で全体より明らかに良い区分が緑 (★)、悪い区分が赤で一目で分かる。

## 5. やらないこと
- 9R 未満の重賞 (稀) の自動検出 (注目レースページに載っていれば拾う)。
- 木曜以前の出馬表 (未公開) の表示。
- 予測・購入への反映。
