## 1. 背景

T40の `_snapshot_runner` は `status`/`scratched` を読むが、本番 `parse_horse_row`
(api/index.py) がこれらを出力しておらず、**取消・除外馬もfield_sizeに数えられ、
採点対象にもなり得る**。

## 2. 要件

パッチをベースに以下で完成させる:

1. **判定関数を行tryの外で安全化**: 取消/除外判定は独立関数にし、判定中の例外で
   馬の行自体を落とさない (**例外時は status未設定=出走扱いへフェイルセーフ**。
   取りこぼしより誤除外の方が害が大きい)
2. 判定は馬名セル・着順セル等の「取消」「除外」「出走取消」表記に基づく。
   **過去走セルに「取消」を含むだけの通常馬を誤検知しない** (位置ベースで判定する。
   T41のA8誤検知修正と同じ教訓)
3. `parse_horse_row` の出力に `status` (normal/scratched/excluded) と `scratched`
   (bool) を追加し、field_size集計・採点対象から scratched/excluded を除外する
4. **通知条件は不変** (jra_ev.py のEV閾値・タイミングに変更なし。除外馬が採点から
   消えることによる確率再正規化のみが波及効果であり、これは正しい挙動)

## 3. テスト (実HTML fixture必須)

1. 取消馬を含む実レースHTML → 当該馬のみ scratched・他馬は不変・field_size減
2. 除外馬 (発走除外) の同上
3. 通常レース → 全馬 status=normal・**既存パース結果とのparity (回帰なし)**
4. 過去走セルに「取消」文字列を含む通常馬 → 誤検知しない
5. 判定関数に壊れたセルを与える → 例外を出さず normal 扱い
6. `python -m pytest tests/ -q` 全体パス

差分 + fixtureテスト + parity確認の報告。0.5日想定。T38切替 (平日) と同時デプロイでよい。
