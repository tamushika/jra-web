# SPEC T48: 障害レースのライブ検知・採点拒否 (+地方交流の構造ガード確認)

共通指示: [README.md](README.md) 参照。タスク管理: `docs/TASKS.md` の T48。
背景: [T46監査 軸1/軸2](../T46-filter-audit.md) — ライブの
`race_type = "ダート" if "ダート" in page_text else "芝"` (api/index.py:443, :1013)
に「障害」という概念が無く、**障害レースを芝の平地モデルで採点しうる**
(学習・評価データはability.db構築時に障害0件 = モデルは障害を一度も見ていない)。
起票: 2026-07-18 上位モデル。

**実装者の担当は実装・テスト・数値報告まで。採否・コミットは上位モデル。**
⚠️ 本番ライブ経路の変更のため、**実装・切替はレースの無い平日**
(T47/T49と同一バッチでよい)。

## 1. 方針

1. **障害レース = 検知して採点拒否 (fail-closed)**。誤って芝として採点する
   現状を止める。「障害レースは解析対象外です」という明示メッセージを返す。
2. **地方交流 (NAR会場) = 既存の構造ガードをテストで固定**。
   ライブのURL会場ガード (api/index.py:1004-1010 の `VENUE_MAP` 照合) が
   JRA10場以外を弾くことを確認・テスト化する (新ロジックは追加しない —
   キーワード「交流」等での推測検知は誤検知リスクの方が大きいため行わない)。

## 2. 検知契約 (障害)

対象はJRA公式出馬表ページ (shift_jis、`CNAME=pw…dde…`) のパース2箇所:
`api/index.py:443` 周辺 (メイン解析) と `:1013` 周辺 (第二パーサ)。

- **判定**: `page_text` に「障害」を含む、または `race_name` に
  「障害」「ジャンプ」「J・G」 (JG格付: J・GI/J・GII/J・GIII表記ゆれ含む)
  を含む場合、`race_type = "障害"` とする。
- 「ダート」「芝」への二値フォールバックはこの判定の**後**に置く
  (障害判定が最優先)。
- **防御的warning**: 障害キーワードが無いのに `distance >= 3700` の場合
  (平地の最長は3600m)、障害の取りこぼし疑いとしてwarningログを出す
  (採点は現状どおり続行 — 誤blockはしない)。

## 3. 下流の挙動

1. **Web解析 (api/index.py)**: `race_type == "障害"` のレースは馬別スコアを
   計算せず、「障害レースは解析対象外 (平地モデルのため)」を明示表示。
   HTTP 200のまま (エラー扱いにしない)。
2. **EV監視 (jra_ev.py)**: 障害レースは監視対象から除外し、1行ログ
   (`障害レースのため監視対象外: <会場R>`)。⚠️ **通知条件 (LINE=5分前×EV≥1.3、
   Discord/ブラウザ発火条件) と通知系関数は変更しない** — 母集団の是正であり
   条件変更ではない。通知関数はレビューでAST比較検証する。
3. **WIN5 (jra_win5.py)**: 障害はWIN5対象外のため影響なし (変更しない)。
4. **T49との整合**: 採点拒否の表示パターンはT49の「初出走」表示と同じUI要素を
   使ってよい (実装を共通化してよいが、判定は独立)。

## 4. テスト

1. **実HTML fixture**: 障害レースのJRA公式出馬表ページを1件取得してfixture化する
   (毎週土日に障害レースはほぼ必ずある。出馬表は前日昼公表のため、
   金曜午後〜土曜に取得可能。取得は数リクエストの読み取りのみ)。
   取得できない場合は実ページの構造を模した合成fixtureで代替し、
   実ページでの確認を「切替日の手動確認項目」として報告に明記する。
2. 障害fixture → `race_type == "障害"`・採点拒否・明示メッセージ。
3. 平地 (芝/ダート) fixture → 従来と完全同一の出力 (非回帰)。
   「サンライズジャンプ」等**馬名に障害キーワードを含むだけ**の平地レースを
   誤検知しないこと (判定はrace_name/コース情報を優先し、馬名列を含む
   page_text全域への「ジャンプ」適用はしない — 「障害」はコース表記
   「障害・芝」等で必ず出る)。
4. distance≥3700 warning の発火と、3600以下での非発火。
5. NAR会場URL (VENUE_MAP外の会場コード) が既存ガードで弾かれることのテスト。
6. `python -m pytest tests/ -q` 全体パス。

## 5. 成果物・報告

変更diff + テスト + (fixture取得できた場合) 実障害レースでの表示dump。
過去のロギングDB (data/jra_logging.db) に障害レースの予測・EV通知が実際に
混入していたかの集計を1表報告 (遡及影響の把握。7/12以降の蓄積は中央平地のみの
はずだが機械確認する)。
