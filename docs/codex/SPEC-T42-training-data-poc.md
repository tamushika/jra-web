## 2. 調査項目 (全てに証拠つきで回答する)

1. **過去履歴の取得可否**: netkeibaの調教ページ (馬別/レース別) から、
   2021年以降の追切履歴を同一定義で取得できるか。何年前まで遡れるか
2. **as-of結合可否**: 調教情報の公開タイミング (追切実施日と公開日の関係) を
   記録できるか。レース前日/当日時点で「その時点で公開済みだった調教」だけを
   再構成できるか (できない場合、バックテストの構築可否に直結する — 最重要項目)
3. **結合キーの安定性**: 馬ID・調教日・トレセン (美浦/栗東)・コース種別
   (坂路/W/P/障害等)・距離・区間ラップを安定して構造化できるか。
   HTML構造のサンプルを添付
4. **例外の扱い**: 未計測・軽め・複数本追い・帰厩直後・外厩の表現のされ方
5. **取得制約**: ページ数見積り (対象馬×履歴)、1秒スリープ下での所要時間、
   日次制限との衝突、ページ構造の改訂リスク (過去ページと現行ページの構造差)
6. **coverage一致**: 学習期間 (2021-24) と直近 (2026) で取得できる項目・粒度に
   差が無いか

## 3. 調査方法の制約

- **読み取りのみ**。取得サンプルは30馬×直近2走分程度に留める (本収集をしない)
- **netkeiba 1秒スリープ厳守**。他のnetkeibaスクレイプタスクと同時実行しない
  (実行前に確認)。日次制限に達したら中断して部分報告
- 本番ファイル変更禁止。調査スクリプトはリポジトリ直下に `poc_` prefixで置く
- ToS上の懸念があれば事実として記載 (判断は上位モデル)
