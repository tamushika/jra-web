# SPEC-T71: EV通知閾値の暫定引き下げ (1.3→1.1、T63裁定までの参考通知)

起票: 2026-08-29 (Fable 5)。ユーザー決定 (2026-08-29): 「T63 v2再登録と併用で、
暫定通知閾値は1.1」。実装: jra-coder。レビュー・コミット: 上位モデル。

## 0. 位置づけ

- T45新モデル下ではEV≥1.3が分布の外側 (p99≈1.07) にあり、2026-07-25以降**通知0件**が
  続いている。T63の正式裁定 (v2ゲート、10月見込み) までの間、**参考情報として**
  閾値1.1で通知を出す
- **購入推奨ではない**。T63の裁定は本変更に影響されない (T63はboard_odds_snapshotsの
  反実仮想再構成であり本番閾値に非依存 — SPEC-T63 v2 §3)
- 1.1はユーザー指定の暫定値。T63裁定で正式値に置き換える (現状維持=1.3への復帰を含む)
- SPEC-T36/T38/T62/T68 に記された「通知条件 (5分前×EV≥1.3) 不変」の制約は、
  本SPECをもって「閾値は設定値 (既定1.3、暫定1.1)」に読み替える。構造
  (5分前ステージ × EV≥閾値 × max_odds 50 × min_prob 0.02) は変えない

## 1. 変更内容

### 1.1 閾値の設定口 (jra_ev.py)

- 環境変数 `EV_THRESHOLD` (未設定なら 1.3) を起動時に読み、`STATE["params"]["ev_threshold"]`
  の初期値とする。`.env` (load_dotenv後) で有効。範囲は既存 `/api/analyze_start` と同じ
  0.8〜3.0 にクランプ、不正値は 1.3 にフォールバックし `[WARN]` を出す
- `_auto_start` は `STATE["params"]` をそのまま使うため、上記で自動起動にも効く
  (`_auto_start` 自体は変更しない)
- `/api/analyze_start` の `ev_threshold` 上書きは従来どおり (ブラウザからの手動指定が優先)

### 1.2 LINE送信閾値の既定値 (jra_ev.py `_send_line`)

- `EV_LINE_MIN_EV` 未設定時の既定を「固定1.3」から「`STATE["params"]["ev_threshold"]`
  (=ピック閾値)」に変更する。明示設定があればそれを優先 (従来互換)
- 理由: ピック閾値とLINE閾値が別々だと、ピック閾値だけ下げても送られない事故が起きる
  (2026-08-29の調査で判明した2段構造)

### 1.3 通知文言 (LINE `_send_line` / Discord `_send_discord`)

- 末尾の固定行「※単勝+複勝の併用が堅い / ワイドは1.6以上全買いで110%」(LINE) および
  「-# 単勝+複勝の併用が堅い / ワイドはoverlay1.6以上全買いで検証上110%」(Discord) は
  **2026-07-13の再検証で否定済みの記述** (ワイド66.6%・運用停止済み) のため削除し、
  以下に置き換える:
  - `※参考情報です (購入推奨ではありません)・閾値EV≥{閾値}`
  - 閾値が 1.3 未満のとき、さらに `※T63裁定前の暫定閾値` を1行追加
- ワイド行の出力ロジック (`alert.get("wide", [])`) は触らない (現状 None で空)
- 先頭行・馬ごとの行の書式は変えない (T68のWIN5通知は無関係・変更しない)

### 1.4 起動時の表示 (jra_ev.py / jra_suite.py)

- 「LINE通知: 有効 (5分前 × EV>=…)」の表示値を、1.2の実効値 (環境変数があればそれ、
  なければピック閾値) に合わせる。ピック閾値も1行表示 (`EV閾値: 1.1 (暫定・T63裁定まで)`
  のように、1.3未満なら暫定の旨を付す)

### 1.5 設定ファイル

- `jra-web/.env` に `EV_THRESHOLD=1.1` を追記 (既存行は触らない。**トークン等の既存値を
  出力・表示しない**)
- `docs/HANDOFF.md` の LINE通知節: `EV_THRESHOLD` の説明を追記、`EV_LINE_MIN_EV` の
  既定を「ピック閾値に追随」に修正、無料枠の見込みを「1.1なら1開催日≈1〜2通
  (T63件数カウント: 1.10で11開催日12件)」に更新

## 2. 変更しないもの

- EV定義 (`win_prob × odds`)、`max_odds`、`min_prob`、5分前/15分前のステージ構造
- `ev_evaluations` ロギング (`threshold` 列に実効閾値が記録される — 既存挙動で十分)
- T63ハーネス・台帳、T70仮想運用 (P3の `P3_EV_THRESHOLD=1.00` は独立)、T68 WIN5通知
- Discord/LINEの送信経路・エラー処理
