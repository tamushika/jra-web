# SPEC-T53: 動的相手関係補正rating (X2, winner-only PL-top1オンライン更新)

起票: 2026-07-23 (Fable 5)。T61討議合意 (docs/T61-accuracy-roadmap-discussion.md) の
実行第2弾。**新規データ取得不要** (既存ability.dbのみで構成)。実装者の担当は
数値報告まで。**評価実行は上位モデルがT39台帳へ登録してから**。採否は上位モデル。

## 1. 仮説と位置づけ

現行の as-of集計 (`j_pts`/`f_pts`/`sire_pts`) はいずれも「個体の過去成績の静的平均」で、
**「誰にどの程度の強さの相手に勝ったか」を動的に伝播させる機構を一度も持たない**。
本タスクは「対戦相手の強さを介した能力の相対評価」(Elo/Bradley-Terry型の動的rating)
を、**as-of特徴として現行CLへ1本追加**する形で検証する。ratingそのものを最終予測に
しない (現行モデルの構造を変えない)。

## 2. モデル (T43の教訓を踏まえた設計)

**winner-onlyのPlackett-Luce top-1オンライン更新のみ**。全着順を使うBT拡張・full PLは
**使わない** — T43で「2着以下の順位情報が勝馬係数を汚染する」ことが確定しており、
同じ汚染経路がratingにも働く懸念があるため。

- レース時点の各馬rating `r_i` から確率 `p_i = softmax(r_i)` (レース内)
- 実現した勝ち馬 (同着は勝ち馬ごとに1イベント、`backtest_ml.fit_conditional_logit`
  と同じ規約) についてのみ、勾配ステップ1回を適用:
  `r_i += η × (1{i=勝者} − p_i)` (レース内の全出走馬に適用。これは現行CLの
  尤度関数そのものをオンライン/逐次SGDで解いているのと数学的に同型 — 新しい
  目的関数を持ち込むわけではない)
- **as-of保証**: 日付昇順で処理し、あるレースの特徴量には**その日より前**の
  ratingのみを使う (T44と同じ日付原子的規約。同日の他レースには波及させない)
- **収縮**: 出走数 `n` が少ない馬 (デビュー直後等) は `shrunk_r = r_i × n/(n+k)`
  で母集団平均 (0) へ収縮する
- **ウォームアップ**: rating系列は2018-01-01から構築し、2021年開始時点で
  ある程度の蓄積がある状態にする (2018-2020分はrating構築専用・特徴としては使わない)
- **分割なし**: 芝/ダート・距離帯等でratingを分割しない (全条件共通の単一rating。
  分割の要否は統一版の結果を見てから別途判断・本タスクでは検証しない)
- 除外: `rank IS NOT NULL` の population filter (取消・除外は含めない、他ハーネスと同一規約)

## 3. 特徴 (2列固定)

1. `opponent_rating_asof`: 上記の収縮後rating (対象レース開始時点、as-of)
2. `opponent_rating_available`: 出走数n≥5 (ratingが最低限意味を持つ目安) で1、それ以外0
   (n<5はフォールバックで`opponent_rating_asof=0`)

## 4. グリッド (2段階・組合せ爆発を避ける)

- **第1段**: 学習率η×収縮定数kの3×3グリッド (例 η∈{0.05,0.1,0.2}, k∈{5,15,40})を
  **本番と同一の固定L2**で評価し、2024選抜の勝馬LogLossが最良の(η,k)を選ぶ
- **第2段**: 選ばれた(η,k)を固定し、L2∈{0.3,1,3}の感度確認のみ行う (追加探索ではなく
  確認)
- 計9+3=12候補相当。baseline (現行21特徴、L2のみ) 3候補も併記

## 5. 評価 (T39プロトコル準拠)

- T41ハーネス (`backtest_feature_pack.py`) を再利用。本番FEATURES・本番artifact不変・
  パックOFFで決定論SHA一致
- 分割: 学習2021-23 / 選抜2024 / 2025・2026H1 historical benchmark固定報告
  (21-24 final-refit + 21-23学習版併記)
- 一次指標 = 勝馬LogLoss (2024選抜)。副 = Brier・top-k・市場フロア・
  WIN5開催日paired・**人気帯別内訳** (人気に現れていない相手関係の強さが
  効くなら人気薄側で効くはず、の確認)・rating分布の健全性 (経験馬と新馬で
  分散が広がっているか等)
- **計算上の注意**: rating系列は年ごとに独立計算できない (状態が時系列で連続する)。
  (η,k)候補ごとに2018-01-01〜2026-06-30を1回通しで構築すること

## 6. テスト

1. as-of: 対象レース当日・未来の結果がratingに反映されない (合成データ)
2. winner-only更新: 2着以下の着順情報が勾配に一切使われないこと
3. 同着の扱いが `fit_conditional_logit` と同一規約であること
4. 収縮 (n/(n+k)) の単調性・n=0で0
5. ウォームアップ期間 (2018-2020) のデータが2021年以降の特徴計算に反映されるが、
   2018-2020自体は選抜・評価に使われないこと
6. パックOFF決定論SHA一致・`python -m pytest tests/ -q` 全体パス

12候補+baseline 3候補の数値レポート (構成×3期間・人気帯別内訳・rating分布)。
解釈・採否は上位モデル。7-15日想定 (状態系列の1回通し構築が計算上のボトルネック)。
