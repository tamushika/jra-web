# SPEC T49: デビュー馬 (過去走ゼロ) のライブML除外統一

共通指示: [README.md](README.md) 参照。タスク管理: `docs/TASKS.md` の T49。
背景: [T46監査 軸4](../T46-filter-audit.md) — 学習=完全除外 / ライブ=フォールバック値で
採点 / 評価既定モード=含む、の3経路不統一。
**2026-07-18 ユーザー決定: 「除外に統一」** (ライブはデビュー馬のMLスコアを出さない)。
起票: 2026-07-18 上位モデル。

**実装者の担当は実装・テスト・数値報告まで。採否・コミットは上位モデル。**
⚠️ 本番ライブ経路の変更のため、**実装・切替はレースの無い平日** (T47/T48と同時でよい)。

## 1. 方針 (決定済み)

学習 (`backtest_ml.build_dataset` の `if not prior: continue`) と整合させ、
**過去走ゼロの馬にはMLスコアを出さない・EV対象にしない**。
フォールバック値 (prev_rank=10 / ln_interval=ln(30) / weight=470 等) で作った
「根拠のない数値スコア」の表示・通知を止めることが目的。

## 2. 変更契約

1. **ML採点の抑止**: `api/scoring.py` の ML 経路で、`n_prior == 0`
   (`_ml_features` が既に算出。定義=学習側 `prior` と同じ「直近4走ウィンドウが空」)
   の馬は `compute_score_ml` 相当の結果を **None** とし、呼び出し側は
   「初出走」であることを表示用 details に明示する。
2. **Web表示**: ML由来スコア欄は「初出走」表記 (数値を出さない)。
   **書籍ルールベースの複勝率スコア (compute_score) と血統・枠等のルール表示は
   変更しない** (デビュー馬にも意味があるため。本SPECはML経路のみ)。
   T36の複勝率βも学習定義と同じ除外に従う (place model側に同種の
   フォールバックがあるか確認し、あれば同様にNone・報告)。
3. **EV監視**: `jra_ev.py` は ml_score None の馬を従来どおり対象外とする
   (現行の `ml_score is not None` 暗黙フィルタが明示的に機能する形になる)。
   除外が起きたことを1行ログ (`初出走のためML/EV対象外: <馬名>`) に残す。
4. **WIN5**: `jra_win5.py` の対象レースにデビュー馬がいる場合、その馬は
   買い目候補から外れるが、**レース自体の解析・他馬の確率計算・頭数は不変**
   (確率正規化の母集団から抜くのではなく、スコア無し馬として扱う。
   実装前に現行の None 耐性を確認し、落ちるなら安全化する)。
5. **判定のfail-closed性に注意**: 過去走パース失敗でも hist が空になり得る。
   その場合も抑止してよい (でっち上げスコアより安全側)。ただし
   「新馬戦以外でフィールドの過半がn_prior=0」の場合はパース異常の疑いとして
   警告ログを出す (採点は抑止のまま)。
6. **通知条件は不変** (LINE=5分前×EV≥1.3、Discord/ブラウザ発火条件)。
   `refresh_and_alert`/`_send_line`/`_send_discord` 等の通知関数は変更しない
   (レビューでAST比較検証する)。

## 3. 評価経路の扱い (本SPECでは変更しない)

- ML評価経路 (backtest_ev.py / build_dataset系) は既に除外済み = 整合。
- `backtest_win5.py` 既定モード (Webスコア評価) はMLと別系統のため対象外。
  監査で記録済みの既知差として維持する。

## 4. テスト

1. n_prior=0 の合成馬で ML スコアが None・details に初出走表記
2. n_prior≥1 の馬のMLスコアが**変更前と数値一致** (非デビュー馬への非回帰)
3. EV: デビュー馬がEV計算・通知候補に入らない + 除外ログ
4. WIN5: デビュー馬入りレースで解析が完走し他馬の確率が不変
5. 過半n_prior=0の警告ログ
6. `python -m pytest tests/ -q` 全体パス

## 5. 成果物・報告

- 変更diff + テスト。過去のシャドーEV通知ログ (data/jra_logging.db) に
  デビュー馬が何件混入していたかの集計を1表報告 (遡及影響の把握。修正はしない)。
