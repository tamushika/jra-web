## 実装

- `t50_track_measurements.py`
  - JRA年別ページから開催回PDFを列挙
  - 既存PDFの再利用、リクエスト間隔1秒以上、連続失敗10回で停止
  - 旧形式（2021～2024）と新形式（2025～）を別パーサで処理
  - 事前測定行と開催日行を `is_race_day` で分離
  - SQLiteへ `(date, venue)` 単位で再開可能なupsert
- 生成先: `data/t50/track_measurements.sqlite`（研究用ローカルデータ、gitignore対象）
- raw PDF、年別HTML、`coverage.json`も `data/t50/` に保存する。
- `published_at`は全行NULL。新形式の測定時刻だけを
  `cushion_measured_at` / `moisture_measured_at` にJSTで保存する。

実行例:

```powershell
python t50_track_measurements.py --from-year 2021 --to-year 2026
```

## 例外処理と監査性

1. [2021年第6回中京PDF](https://www.jra.go.jp/keiba/baba/archive/2021pdf/chukyo06.pdf)
   はテキスト層がない画像PDFだった。2倍レンダリングで全45数値を目視確認し、
   [転記fixture](fixtures/T50-2021-chukyo06-transcription.txt)を追加した。
   PDFのSHA-256が一致する場合だけ適用するため、JRA側で差し替えられた場合は
   自動的にパース失敗となる。
2. 2022年第1回阪神PDFのテキスト層に `8..8` という小数点重複が1セルあった。
   可視PDF上の値は `8.8` であり、数字間の連続小数点だけを正規化した。
3. 2021～2024年は測定・公表時刻をPDFから独立検証できない。標準化用の
   歴史平均を含め、このas-of制約をT39台帳へ明記する必要がある。
