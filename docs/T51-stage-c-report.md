## 実地で判明した現行DOM差分

初回取得で現行成績表のヘッダーが `馬 番` のような空白入りになっており、旧完全一致では斤量0件となった。ヘッダー内空白を正規化し、空のキャッシュを再取得対象に変更した。また条件欄のハンデ表記が `(ハンデ)` のため、空白境界ではなく語の包含で判定するよう修正した。既知の目黒記念を含む9R以降212レースを再確認し、36レースをハンデとして保存した。

途中停止時にも再開可能となるよう、キャッシュはレースごとに原子的保存し、Windows共有違反には短い再試行を行う。専用回帰テストは8件、全体回帰は **477 passed / 2 skipped** で通過した。

取得本体は当初見積り634リクエスト相当。DOM診断、途中再開、ハンデ判定の限定再確認212ページを含むため、当日の実消費は概算約850リクエストとなった。外部スクレイプとの併走はしていない。

## 定常経路と再発防止

`extend_ability_from_neon.py` はNeonの `斤量` 列を通常どおり取り込む。今回の原因は4月25日から6月の上流バッチにおける列欠落だった。今後は延伸後に新規バッチの `kinryo IS NULL` 率を確認し、連続開催日で急増した場合は次の学習・評価を封印してソースドリフトとして扱う。

Stage Cは完了。以後の実験は新DB SHA-256 `7ffcfe21618612b603053544cd888eec637b6fdf69192470c5751c5f89b00c79` を封印値として使用する。
