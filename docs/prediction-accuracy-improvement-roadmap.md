## 1. 目的

現行予測を単に複雑化するのではなく、次の3つを分けて改善する。

1. **WIN5**: 勝ち馬がスコア上位k頭に入る確率と5レース全的中率
2. **Web**: オッズから独立した3着内候補の捕捉率と複勝確率
3. **EV監視**: 予測確率の校正、通知時点で購入可能な期待値、実回収率

モデルの採用判断では、的中率、確率精度、回収率を混同しない。的中率が高いモデルが高回収とは限らず、逆も同様である。

## 2. 現状診断

### 2.1 現行WIN5モデル

- 目的関数: conditional logit（レース内softmax）
- 学習期間: 2021～2025年
- 学習件数: 211,861走
- 特徴量: 21個
- 最大の特徴量: `ln_odds`（標準化係数 -1.43872）
- 次点: `sire_pts`（+0.203191）
- 2025年時系列OOSカバレッジ:
  - k=1: 32.1%
  - k=2: 51.6%
  - k=3: 64.4%
  - k=4: 72.4%

市場人気順との比較は**必ず同一レース集団・同一フィルタで行う**こと。
旧版の表は「全レース集計の市場値」と「9R以降・8頭以上限定のモデル値」を
比較しており不成立だった。同一集団 (9R以降・8頭以上、2025年、

| 上位頭数 | 市場人気順 | 現行WIN5 ML | 差 |
|---|---:|---:|---:|
| 1頭 | 30.6% | 32.1% | +1.5pt |
| 2頭 | 49.4% | 51.6% | +2.2pt |
| 3頭 | 61.9% | 64.4% | +2.5pt |
| 4頭 | 70.6% | 72.4% | +1.8pt |

今後は1番人気・人気上位k頭・市場確率を必須ベースラインとし、
**集団・フィルタ・期間を揃えた比較のみを有効とする**。

## 3. 最優先課題

### 3.1 市場ベースラインの標準化

すべてのバックテストで次を同時に出力する。

- 1番人気
- 人気上位2～4頭
- 市場確率のみ
- 現行モデル
- 新モデル

市場確率は単純な`1 / odds`ではなく、レース内で合計1になるよう正規化する。

```text
raw_market_probability_i = 1 / odds_i
market_probability_i = raw_i / sum(raw_j)
```

人気順位と正規化市場確率は、別モデルではなく同じ**M0市場ベースライン**の2つの使い方として扱う。

- 順位評価: JRA人気順位を使い、top-k捕捉率を測る
- 確率評価: 正規化オッズを使い、Log Loss、Brier Score、WIN5配分を測る

単純なオッズ確率モデルは人気順と同じ並びになるため、M0とは別にM1として数えない。確率値の校正には意味があるが、単調変換だけではtop-k順位は変化しない。

モデルが手調整スコアを上回っても、市場を下回る場合は純粋な的中精度向上とは判断しない。

**比較の前提 (必須)**: ベースラインとモデルは**同一レース集団・同一フィルタ・
同一期間**で算出する (例: WIN5評価なら 9R以降・8頭以上・オッズあり)。
母集団が異なる数値の突き合わせは§2.1旧版のように誤結論を生むため無効とする。
実装面では `backtest_win5.py --ninki` が同一ハーネスで人気ベースラインを
既に出力するので、これを標準とする。

### 3.2 学習・本番特徴量の一致

確認済みの差異:

| 特徴量 | 学習 | 本番 | 対応 |
|---|---|---|---|
| オッズ | 確定オッズ | 15分前・5分前等 | 時点別スナップショット蓄積後、同時点データで再学習 (Phase C) |
| `pace_fit` | 馬ごとに計算 | 常に0 | 本番計算を実装。なお全馬一律0はsoftmaxの平行移動不変性により確率を歪めない (害はなく、信号を捨てているだけ) |
| 馬体重 | 当該レース値 | 主に前走値 | **当日馬体重をライブ取得** (発走約1時間前に公表されるため取得可能)。発表前／発表後のモデル分離は不要 |
| `grade_pts` | 血統以外ルール | 血統込み | ✅ T8で統一 (ライブのML特徴量を血統以外ルールに合わせた。表示用◎〇△は不変) |

同一の保存済みレースを学習用特徴量生成器と本番特徴量生成器へ通し、全特徴量が許容誤差内で一致する自動テストを追加する。

### 3.3 時系列リークの排除

現在の検証には次のリスクがある。

- 2021～2025集計のコース統計を2025年評価にも利用する箇所がある
  (コース統計の出所 db-keiba は過去時点スナップショットを提供しないため、
  fold別統計は ability.db からの再集計で作る必要がある — Phase B参照)
- 一部の発掘ルール (mined_rules.csv) は2025～2026年を選抜に使用済み
  → 対処は `mine_criteria.py` を「発見2021-23／選抜2024」に組み直して再採掘
- 2025年をモデル・特徴量選択に繰り返し使用している

今後の基本分割:

```text
学習:       2021～2023
調整:       2024
固定テスト: 2025
追加確認:   2026年前半
完全未使用: 2026年後半以降
```

騎手、種牡馬、コース統計、ルール採掘も各foldの学習終了日以前のデータだけで生成する。

## 4. 精度向上施策

### 4.1 比較するモデル体系

今後の比較モデルを次のように定義する。

| モデル | 定義 | 主な目的 |
|---|---|---|
| M0 | 市場人気順位／正規化市場確率 | 必須ベースライン |
| M2 | オッズなし基礎能力モデル | 独自情報だけの予測力を測る |
| M3 | 市場offset＋幅広い基礎能力残差 | 市場へ独自能力を上積みする |
| M4 | 市場＋限定的な過剰人気／過小人気補正 | 市場の系統的な誤差を補正する |

M1は設けない。人気順位とオッズ確率はM0へ統合する。

### 4.2 M3: 市場offset＋独自残差モデル

**優先度: 高**  
**実現性: 高**  
**期待効果: 中（下記の理由で当初想定より控えめ）**

現行モデルは`ln_odds`を通常特徴量として学習している。これを市場予測を基準とした残差学習へ変更する。

**注意**: 現行conditional logitでは `ln_odds` の学習済み係数 (−1.44) が
事実上「学習されたα」として機能しており、既にM3にかなり近い構造になっている
(log(market_prob) と ln_odds はレース内でほぼ線形関係)。したがって
offset固定への変更による精度向上は小幅と見込む。それでもM3化する価値は、
(a) 市場順位を下回らないフロア保証、(b) 独自上積み分の可視化、の2点にある。

```text
market_probability = 正規化した1/オッズ
residual_score = 能力・血統・騎手・距離適性等から計算
final_score = alpha * log(market_probability) + residual_score
final_probability = race_softmax(final_score)
```

比較時はM0、M2、M3に加え、後述するM4を同時に評価する。

利点:

- 市場順位以下へ落ちにくい
- 独自特徴が市場へ加えた上積みを測定できる
- WIN5では市場順位を基本に、根拠の強い馬だけ順位を変更できる
- EVでは市場とモデルの差を明示できる

### 4.3 M4: 市場人気＋過剰人気補正モデル

**優先度: 最優先**  
**実現性: 高**  
**期待効果: 確率校正・WIN5配分・EVで中～高、top-kで小～中**

M4は市場確率を出発点とし、市場が系統的に過大評価・過小評価する条件だけを限定的に補正する。M3が馬の能力全体を扱うのに対し、M4は「市場の間違え方」を対象にする。

```text
market_probability_i = normalized(1 / odds_i)
bias_correction_i = g(前走、人気、騎手、実績、レース条件等)
score_i = log(market_probability_i) + bias_correction_i
M4_probability = race_softmax(score_i)
```

市場の対数確率はoffsetとして固定することを基本とする。これにより、補正根拠が弱い場合はM0へ自然に戻り、市場順位を壊しにくい。

#### M4-A: 市場確率の校正

まず順位を変更せず、オッズが示す確率だけを補正する。

候補区分:

- オッズ帯
- 人気順位
- 頭数
- 新馬、未勝利、条件戦、重賞
- 芝／ダート
- 距離帯
- 発走までの残り時間

例:

```text
市場確率40%の馬が同条件で実際には35%しか勝っていない
→ 40%を35%付近へ校正する
```

M4-Aは単調な補正であれば人気順位を変えない。そのためtop-k的中率は原則変化しないが、次を改善できる。

- Brier Score
- Log Loss
- WIN5の推定的中率
- 1頭固定／複数頭選択の判断
- EV計算

#### M4-B: 馬ごとの過剰人気／過小人気補正

次に、同一レース内で馬ごとの補正を行い、根拠がある場合だけ順位を変更する。

候補特徴:

- 前走着順
- 前走人気
- 前走着順と前走人気の差
- 今回市場順位とM2能力順位の差
- 前走大差勝ち／大敗
- 同コース好走歴
- クラス実績
- 距離延長／短縮
- 昇級初戦
- 休み明け
- 騎手人気と騎手実績の差
- 血統人気と条件適性の差
- 独自能力に比べて市場支持が強すぎる／弱すぎる状態

レース単位では次も使用候補とする。

- 1番人気と2番人気のオッズ差
- 上位人気への投票集中度
- オッズ分布のエントロピー
- 頭数
- レースクラス
- 発走までの時間
- 複数時点での人気順位・市場確率の変化

現行モデルにもM4的な兆候がある。オッズを考慮した後の係数が、`prev_rank`は前走凡走馬を戻す方向、`course_fit`とクラス実績は分かりやすい実績を引き下げる方向であり、市場が前走好走や明確な実績を過剰評価している可能性を示している。ただし、現行モデルでは基礎能力とバイアス補正が混在しているため、M4として分離して検証する。

#### M4の価値

| 指標 | 期待効果 |
|---|---|
| top-1的中率 | 小～中 |
| top-2～4捕捉率 | 小～中 |
| Brier Score／Log Loss | 中 |
| WIN5点数配分 | 中～高 |
| EV判定 | 中～高 |
| 説明可能性 | 高 |

M4は市場を基本とするため、M2より市場精度へ到達しやすく、M3より補正理由を説明しやすい。一方、M4-Aだけでは順位が変わらず、top-k改善は生じない点に注意する。

#### 過補正の防止

- 市場確率をoffsetとして固定する
- 補正係数へ強い正則化をかける
- 1頭あたりの補正幅に上限を設ける
- 市場順位変更に必要な最小根拠数を設ける
- 「人気馬が負けた」という単発結果で過剰人気と判定しない
- 同条件の多数レースで市場予測と実勝率の差を確認する

### 4.4 レース内相対特徴量

**優先度: 高**  
**実現性: 高**  
**期待効果: 中～高**

追加候補:

- タイム指数のレース内順位
- タイム指数とメンバー中央値の差
- レース内最高値との差
- 騎手点・血統点・斤量のレース内偏差
- 直近走指数と過去4走平均の差
- 過去4走の平均、最大、傾向、分散
- 昇級／降級と能力差の交互作用
- 上位2頭の予測確率差
- 市場人気順位と独自順位の差

conditional logitはレース内比較を目的にするため、絶対値だけでなく相対値を入力する価値が高い。

### 4.5 時点別オッズ・オッズ変化

**優先度: 高**  
**実現性: 中（データ蓄積が必要）**  
**期待効果: EV精度で高**

固定取得時点:

- 30分前
- 15分前
- 10分前
- 5分前
- 2分前
- 可能なら締切直前

追加特徴:

```text
odds_drift = log(current_odds / previous_odds)
market_probability_change = current_market_probability - previous_market_probability
popularity_change = current_popularity - previous_popularity
```

さらに次を検討する。

- オッズ分布のエントロピー
- 1番人気と2番人気の確率差
- 市場支持が継続しているか、一時的変動か
- 独自確率と市場確率の差が複数スナップショットで維持されているか

途中オッズモデルは確定オッズで学習しない。同じ「発走までの時間帯」のデータで学習・検証する。

### 4.6 Web用複勝確率モデル

**優先度: 高**  
**実現性: 中～高**  
**期待効果: Webの好走馬抽出で中～高**

目的変数を3着以内とし、オッズを除外したモデルを作る。

```text
target = 1 if finish_position <= 3 else 0
features = 能力、血統、騎手、枠、距離、馬場、斤量、近況
output = calibrated_place_probability
```

評価:

- 上位1・3・5頭の複勝捕捉率
- Brier Score
- 確率帯別の予測複勝率と実複勝率
- 人気帯別の市場超過率
- オッズを使わない状態での複勝回収率

現行の手動Webスコアは説明用として残し、確率モデルを別列でシャドー表示して比較する。

### 4.7 騎手・厩舎のローリング成績

**優先度: 中**  
**実現性: 中**  
**期待効果: 中**

候補:

- 騎手の直近30日／90日勝率
- 騎手×競馬場×芝ダの直近成績
- 厩舎の直近30日／90日成績
- 騎手変更
- 騎手×厩舎の組み合わせ
- 休み明け成績
- 昇級初戦成績

対象レースより未来を含めないローリング集計とし、小サンプルは全体平均へ階層的に収縮する。

### 4.8 血統特徴の拡張

**優先度: 中**  
**実現性: 中**  
**期待効果: 中**

父特徴は既に2025年OOSのk=1を約1.0ポイント改善した。次の候補は以下。

- 母父×芝ダ
- 父×母父
- 父×距離帯
- 父×馬場状態
- 父×年齢
- 血統×初コース
- 血統辞典の買い／消し判定

ルール採掘は学習期間内で完結させ、固定テスト期間を選抜へ使用しない。

### 4.9 非線形モデル

**優先度: 低（特徴拡張後に再評価）**  
**実現性: 中**  
**現時点の期待効果: 低**

現行21特徴量ではLightGBM LambdaRankはconditional logitとほぼ同等だった。次の特徴が揃ってから再評価する。

- オッズ変化
- 母父
- 騎手／厩舎ローリング成績
- 相対タイム
- ペース×脚質
- 血統×コース交互作用

候補はLightGBM LambdaRank、CatBoost Rankingとする。ニューラルネットはデータ定義と検証基盤が安定するまで優先しない。

## 5. EV判定の改善

確率の点推定だけで通知せず、不確実性と継続性を考慮する。

候補:

- 複数スナップショットでEV条件を満たした場合だけ通知
- 市場確率との差が一定以上の場合だけ通知
- データ欠損が多い馬は閾値を引き上げる
- 勝率を市場側へ収縮した場合でもEV>1になる馬を優先
- 確率の下側信頼限界でEV>1を満たすか確認
- 通知時点別に閾値を分ける

これらは通知数を減らす可能性があるため、的中率だけでなく回収率、見逃した利益、通知件数を同時評価する。

**2026-07-13追記**: 組み合わせ馬券は検証完了。**ワイド overlay≥1.6 全買い**
(Harville式・減衰λ=0.7、`api/combo_probs.py`) を採用し、監視・通知に実装済み
(2025年110.1%／2026年OOS 110.0%、実払戻ベース)。馬連は2026年OOSで再現せず
不採用、1レース1点方式も劣後。ワイドも単勝・複勝と同様に
実運用ログでの実測回収評価の対象に含めること。

## 6. 評価設計

### 6.1 必須指標

#### WIN5

- top-1～top-8カバレッジ
- 点数別の5レース全的中率
- 市場人気順との差（同一集団・同一フィルタで）
- 推定的中率の校正
- **配分レベルのpaired比較**: 頭数カバレッジだけでなく、実際の点数配分
  (`allocate_picks_prob`、150点等の同一予算) を新旧モデルで同一週に流し、
  5連的中率を直接比較する。カバレッジ改善が配分改善に化けない事例があるため必須

#### Web

- top-k複勝捕捉率
- Brier Score
- 確率校正
- 人気帯別複勝率

#### EV

- Log Loss
- Brier Score
- Calibration Error
- 単勝／複勝回収率
- 通知時点別回収率
- 通知時オッズ→最終オッズの変化
- データ欠損率、通知失敗率

### 6.2 統計的な確認

- 同じレースで旧モデルと新モデルを比較するpaired bootstrap
- 的中率・回収率に95%信頼区間を付与
- 回収率が高配当1件だけに依存していないかleave-one-hit-outで確認
- 競馬場、距離、芝ダ、人気帯別で改善方向が一貫するか確認
- 複数の閾値を試した場合は最良値だけを報告せず、全結果を保存

### 6.3 実運用シャドー評価

新モデルは既存通知へ直ちに反映せず、次を並行保存する。

```text
production_probability
candidate_probability
market_probability
production_decision
candidate_decision
```

最低4開催、可能なら8～12週のシャドー運用後に本番昇格を判断する。

**実現手段 (既存基盤で可能)**: ログ基盤 (`api/logging_store.py`、
data/jra_logging.db) は `model_version` 単位で予測を保存できるため、
候補モデルを別 model_version の prediction_run として並行記録するだけで
シャドー評価になる。実績ダッシュボード (`start_perf.bat`、port 5004) が
モデル版別に的中率・回収率を集計するので、追加開発はほぼ不要。

## 8. 採用ゲート

新モデルは次を満たすまで本番へ切り替えない。

1. 市場人気のtop-kカバレッジを下回らない（同一集団・同一フィルタで比較）
2. 現行モデルよりLog LossまたはBrier Scoreが改善する
3. 2025固定テストと2026追加確認で方向が一致する
4. 競馬場・距離・芝ダの主要区分で重大な劣化がない
5. 95%信頼区間またはpaired bootstrapで改善の安定性を確認する
6. **WIN5配分レベルのpaired比較** (同一予算の点数配分シミュレーション) で
   現行を下回らない — カバレッジ改善のみでの採用は不可
7. 4開催以上のシャドー運用で欠損・処理失敗がない
8. 回収率が少数の高配当だけに依存していない
9. モデル版、設定ハッシュ、学習期間、特徴量定義をログへ保存する

## 9. 今すぐ着手する推奨順序

1. **Phase A: 市場ベースラインの標準化と特徴量一致テスト**
   (＋2026年オッズ432走の埋め戻し — 数時間で完了)

## 10. 今回は優先しない案

- 現特徴量のままモデル種類だけを増やす
- 2025年の同じテストセットを繰り返し見ながら調整する
- 数開催の実運用結果だけでEV閾値を変更する
- 的中率だけでEVモデルを評価する
- 高配当1件を根拠に回収率改善と判断する
- 途中オッズ運用を確定オッズバックテストだけで正当化する

精度向上の中心は、モデルの複雑さではなく、市場に対する増分情報、学習／本番一致、厳密な時系列評価、購入可能時点のデータ蓄積である。
