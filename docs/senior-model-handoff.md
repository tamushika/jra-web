## 2. 検証の作法 (このプロジェクトの憲法)

1. **凍結分割**: 学習2021-23 / 調整2024 / 固定テスト2025 / 追加確認2026H1 / 完全未使用2026H2。
   2025を見ながらの再調整は禁止 (調整は2024で完結)
2. **同一集団比較**: ベースラインとモデルは同一レース集団・同一フィルタ・同一期間でのみ比較
   (WIN5評価 = 9R以降・8頭以上・オッズあり)。母集団が違う数値の突き合わせは無効
   — 他LLMのロードマップ初版がこれで誤結論を出した実例あり (roadmap §2.1)
3. **採用ゲート**: roadmap §8 の9項目。特に「市場人気top-kを下回らない」
   「WIN5配分レベルのpaired比較」「少数の高配当依存でない」
4. **負の結果も記録**: 不採用の判断と理由を TASKS.md / 各docsに残す。無検証の再導入禁止
5. **実装と判断の分離**: Codex/下位モデルには数値の報告までさせ、解釈と採否はあなたが行う。
   下位モデルの「検証しました」を採否根拠にする場合、採用に関わる数値は自分で再実行または
   スポットチェックする (T4では自分で参照値一致を確認してから承認した)

## 5. レビュー時のチェックリスト

Codex/下位モデルの成果物レビューで毎回確認していたこと:
1. スコープ逸脱がないか (SPECにない本番ファイル変更、余計なリファクタ)
2. **通知条件が不変か** (LINE=5分前×EV≥1.3、Discord/ブラウザの発火条件) — jra_ev.py を触る変更は必ずdiffで確認
3. バックテストに `--write` を付けていないか (本番設定の上書き)
4. テストが実際に走って全パスか (`python -m pytest tests/ -q`、自分で再実行)
5. 単調性・レース内確率総和=1 など数学的不変条件のassertがあるか (M4系)
6. 表示用の値 (◎〇△等) とML特徴量を混同していないか
7. コミットは自分で行う。メッセージ末尾に `Co-Authored-By:` (Codex成果物なら Codex と自分の両方)。
   jra-web でコミット→push→**親リポジトリのsubmoduleポインタも更新**

## 6. 環境の落とし穴 (実際に踏んだもの)

- **ポート二重バインド**: Windowsでは旧プロセスが残ったまま同ポートに新プロセスが起動でき、
  旧が応答し続ける。5003/5004で2回発生。T28のガード実装で解消予定。
  調査は `Get-NetTCPConnection -LocalPort <port>` → PID → StartTime確認
- **Pythonが複数ある**: venv (`..\Scripts\python.exe`)、batが使う `%LocalAppData%\Python\bin\python.exe`、
  Codexが使う `c:\Users\owner\project\jra-runtime\Scripts\python.exe`、野良の pythonw。
  「どのPythonで動いているか」を常に疑う (7/11のLINE通知全損の一因はbat側Pythonにdotenv未導入)
- **ロギングDBはUTC保存**: 表示はJST変換 (_to_jst)。日付キー (race_id先頭8桁) はJST基準
- **CRLFファイル**: HTML等はPythonで編集時 `.replace("\r\n","\n")` で読み `newline="\n"` で書く
- **Bash heredocのバックスラッシュ**: `\\n` が化ける。編集スクリプトはWriteツールでファイルに書いてから実行
- **netkeiba**: 1秒スリープ厳守。血統は /horse/ped/<id>/ (2026-07仕様変更)。日次制限あり
  (大量取得タスクは同時に走らせない)
- **runsテーブルは列が増える**: 列名明示INSERTでないと落ちる。extend_ability_from_neon.py は
  fukusho_pay を退避・復元する (2026-07-13修正済み。同種の列追加時は同じ配慮)
- **.env (DATABASE_URL, GEMINI_API_KEY, EV_LINE_CHANNEL_TOKEN, EV_DISCORD_WEBHOOK) は絶対にコミットしない**
