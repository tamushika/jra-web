# ローカル予想アプリの信頼性改善 (2026-09-19)

ユーザー依頼の順序: ①確率計算の品質保証 → ②収集状態の表示 → ③詳細画面の同期。
予測モデル・係数・通知閾値・事前登録済み評価契約・既存の結果DBは変更しない。

## 1. 確率計算の品質保証

- ML採点を `ml / fallback / unavailable` に分け、失敗理由を返す。
- 参考スコアは保持するが、ML確率に混ぜず、共通ログのMLスコア欄にも保存しない。
- EVとMLモードのWIN5は、取消馬を除いた全頭 (最低2頭) の有限な正常ML採点を要求する。
- 部分集合を100%に再正規化しない。品質不足時は勝率・EV・WIN5配分を停止し、採点頭数と理由を表示する。
- ML勝率が計算できない場合、WIN5を暗黙に別方式へ切り替えない。
- 正常な全頭データのスコア・確率・配分は従来どおり。通知の判定関数は凍結ソースを維持する。

## 2. 収集状態の表示

- 解析の処理件数と成功件数を分離し、失敗・対象外件数を表示する。
- 当日分の最終取得・有効オッズ取得・保存成功・現在のエラーを表示する。
- 30/10/2分前の記録は、待機・保存済み・品質不足・未取得・未確認を区別する。
- 既存の `checked` は断念時にも立つため、保存成功の証拠に使わない。
- 古い復元レコードの観測情報は未確認とし、監視巡回時刻と実データ取得を区別する。
- 解析完了後も状態確認を継続。HTTPエラー・タイムアウトは明示し、自動再確認する。

## 3. 詳細画面の同期

監視が既に取得したキャッシュだけを使って、同じレースの新しい情報を反映する。
キャッシュ照会のために外部サイトを再取得しない。
手動選択・印・並び順・履歴選択・閲覧位置を維持し、取得時刻・経過時間を表示する。
古い日付、未取得、通信失敗を区別し、レース切替前の遅い応答を採用しない。

## 運用上の注意

これらは予測の誤表示・収集漏れを防ぐ改修であり、的中率向上を検証したものではない。
欠損レースでの通知・WIN5配分は減る可能性がある。未採点馬への確率補完は行わない。
稼働中のプロセスにはPython変更が自動反映されないため、反映時にスイートの再起動とブラウザの再読込が必要。
再起動は収集・通知を中断しない時間帯に行う。

## 検証結果

- Python 3.12で `pytest tests -q -rs -p no:cacheprovider` を実行: **948 passed / 2 skipped**。
- スキップはWindowsのシンボリックリンク作成権限不足1件と、検証専用 `TEST_DATABASE_URL` 未設定1件。
- `script.js` とEV/WIN5の埋込JavaScriptはNode構文検査成功。
- 新規UIテストはNode VMの模擬DOM・通信・時計を使用し、応答競合、タイムアウト、操作状態保持、判定不可時の通知抑止を検証。
- 既存のモデル成果物ハッシュ、凍結通知関数、評価契約の回帰テストも成功。
- 稼働中プロセスの停止・再起動、モデル再学習、成績評価、外部デプロイは実施していない。
