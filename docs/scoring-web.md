# jra-web (Web版) スコア算出仕様

対象: https://jra-web.vercel.app/ の出馬表テーブル「スコア」列
実装: [api/scoring.py](../api/scoring.py) `compute_score()` / 設定: [api/data_files/common/score_weights.json](../api/data_files/common/score_weights.json)
呼び出し: `/api/scrape` の馬ループ ([api/index.py](../api/index.py))

## 基本設計

- **複勝率ベースの加点方式**: 各ファクターについて「その条件の複勝率がコース全体平均(baseline)からどれだけ乖離しているか」を点数化し、線形に合算する
- **オッズ・人気は使わない**(市場から独立した評価。WIN5版との最大の違い)
- 重み・パラメータはすべて score_weights.json に外出しされており、コード変更なしで調整可能
- 各馬の内訳はスコアセルのtooltip(`score_details`)に表示される

## スコア構成(合算順)

### 1. コースバイアス系ファクター(db-keiba統計)

データ: `api/data_files/<場>/factors/<芝|ダート><距離>.csv`(db-keiba.com の2021-2025集計、99コース。`scrape_dbkeiba.py`で更新)

| ファクター | 照合キー | 重み |
|---|---|---|
| 種牡馬 (father_w) | 父の名前(NFKC正規化・完全一致→3文字以上一意の部分一致) | 0.5 |
| 騎手 (jockey_w) | 騎手名(減量記号・ドット除去) | 1.0 |
| 枠順 (frame) | 枠番 `N枠` | 0.5 |
| 脚質 (averunningstyle) | ◀◁矢印→逃げ/先行/差し/追込 | **0.0(無効)** |
| 距離変更 (distance) | 前走距離との実差分→7段階ラベル(500m以上延長〜500m以上短縮) | 0.8 |
| コース替わり (surface) | 前走芝ダ→今回芝ダ(芝→芝 等) | 0.8 |
| 所属 (stable_trainer) | 美浦/栗東 | 0.5 |

**1ファクターの得点式**:
```
dev    = (該当行の複勝率 − baseline複勝率) / 100
shrunk = dev × starts / (starts + 20)          # 小サンプル収縮 (shrinkage_n0=20)
pts    = clamp(100 × shrunk, −8.0, +12.0) × 重み
回収率ボーナス: 単回≧100 または 複回≧100 なら +1.5 × 重み
出走数 < 5 (min_starts) のファクターは無効
```
factors CSV が無いコースはバイアス系のみスキップし、以下の成分だけで部分スコアを算出する。

### 2. 血統辞典 買い/消し(競馬血統総辞典)

`sire_buysell_rules.json`(86ルール、`compile_buysell_rules.py`で条件文を構造化)と照合。
条件: 芝ダ/距離/場/直線長短/性別/枠/前走馬体重/距離延長/クラス/母父系統/テン・上がりパターン(近似)。
判定不能な句(母父の米国型等)は加点しつつ「要確認」として表示。

- 買い該当: **+3.0** / 消し該当: **−2.0** / 合計 ±6.0 でクランプ

### 3. 能力サブスコア(馬自身の評価)

直近4走(hist)から算出。重み 1.0。

| 成分 | 式 | パラメータ |
|---|---|---|
| タイム指数 | `(基準タイム + 当日馬場差 − 走破タイム) × time_k × 鮮度重み` の最良走。クランプ±8 | time_k=1.5, 鮮度 1.0/0.85/0.7/0.55 |
| クラス実績 | `クラス点(新馬10〜重賞70) × 着順係数 × class_k × 鮮度重み` の最良走 | class_k=0.06, 着順係数 1着1.0/2着0.7/3着0.5/4-5着0.25 |
| 上がり質 | 直近4走の上がり順位比率の最小値 ≤ 0.3 なら加点 | +3.0 |

- 基準タイム: `venue_standard_times.json` — 場×芝ダ×距離×クラス×馬場状態別の勝ちタイム中央値(2016-2023集計)
- 馬場差: `track_variants.json` — 日別×場別×芝ダ別の時計補正(track_variant=true)。**毎週月曜にGitHub Actionsが自動更新**(馬場の年次高速化ドリフト: 2016年+0.11秒→2026年−0.65秒を吸収)

### 4. 道悪適性(当日馬場が稍重/重/不良のときのみ)

直近4走に道悪と良馬場の**両方**の経験がある馬に限り、ベスト着順を比較:
- 道悪の方が2着以上良い: **+2.0** / 2着以上悪い: **−1.5** / それ以外・片方のみ経験: 増減なし
- 当日馬場は `fetch_baba_info`(JRA含水率ページ)から取得

### 5. 好走条件判定ボーナス(ルール別重みつき)

`criteria.csv`(◎〇△判定、`analysis.evaluate_ultra`)の該当ルールごとに **グレード点 × ルール重み** を計算し、その最大値を加点:
- グレード点: **◎ +8.0 / 〇 +4.0 / △ +1.5**
- ルール重み(優先順): ① criteria.csv **7列目**の手動重み → ② `criteria_weights.json` のバックテスト自動算出重み → ③ 1.0
- 自動重みの生成: `python backtest_criteria.py --gen-weights`(ability.db が必要)。
  式: `weight = clamp(1 + 4×(ルール複勝率 − 場複勝率)×n/(n+20), 0.5, 1.5)`(小サンプル収縮つき)
- 血統・生産者・減量条件を含むルール(全体の約半分)は ability.db で検証不能のため自動重みなし(=1.0)。手動重みでのみ調整可能
- 該当ルールと重みはスコアtooltipに表示(重み1.0のルールは重み表記省略)

## スコアがnullになる条件

算出根拠が1つも無い場合(履歴なし かつ factors未整備 かつ判定・血統辞典該当なし)のみ `score: null`。

## 検証根拠(バックテスト、詳細は score_weights.json の backtest_meta)

| 項目 | 結果 |
|---|---|
| 全体(2024-25, n=91,572) | スコア5分位で複勝率16.1%→35.9%と完全単調、最上位単回収88.8% |
| 能力(per-runner, n=84,354) | 複勝率8.8%→35.2%、**全人気帯で市場超えのリフト** |
| 2026年OOS(n=8,639) | 単調性維持(17.1%→33.6%)= 汎化確認 |
| 脚質 | corner_4プロキシで判別力なし→重み0 |
| 種牡馬 | 2026年OOSで予測力弱(ρ≒0.02-0.16)→重み半減0.5 |
| 血統辞典 | 買い=方向一致72%で支持、消しは検証不能→−2.0に緩和 |
| 道悪適性 | 相対適性のみ有効(道悪日単回収94.4% vs 良馬場日65.9%)。単純フラグはプラセボ陽性で不採用 |

## 更新運用

- factors CSV: `python scrape_dbkeiba.py --force`(半年ごとにGitHub Actionsが自動実行)
- 馬場差: 毎週月曜自動(`update-track-variants.yml`)
- 重み調整: `backtest_score.py`(Neon優先/`--sqlite`)
