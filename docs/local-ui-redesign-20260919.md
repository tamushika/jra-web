# ローカルUI改修（2026-09-19）

## 変更内容

- 共通のダークテーマ、配色、余白、入力部品、フォーカス表示を整理。
- 統合画面の操作・タブ・稼働状態を分離。収集状況は短い要約と展開式の詳細に変更。
- オッズ監視の長い未採点理由が隣のセルへはみ出す問題を修正。理由別に馬番を集約し、展開して確認できるようにした。
- 監視レース数・EV対象数・判定不可数を表示。「すべて／EV対象／判定不可」で絞り込める。フィルター変更による空行や会場の並び替わりを防ぐ。
- WIN5対象5レースをカード化し、取消・除外を除いた出走頭数を表示。未取得は0頭と区別。同日・同レースのEV取得済みデータを再利用し、解析時にも更新する。
- WIN5のURL編集、馬別採点、判定不可理由は必要なときに展開。
- WIN5のURL編集後は古い頭数・解析表示を解除し、変更前の応答が戻っても上書きしない。
- 実績ダッシュボードを「概要／モデル比較／EV通知／WIN5／仮想運用／レース・日別明細」に整理。
- 概要は選択した1モデルの結果確定数・的中率・回収率を表示。モデル間の重複レースを合算しない。実購入と100円仮想投資の区別を維持。
- 日別グラフは画面幅変更時にも再描画。モデル選択はAPIの返却順が変わっても同一モデルを保持。
- 詳細な表は表の内部だけ横スクロールし、ページ全体の横はみ出しを抑制。

## 変更しない範囲

今回のUI改修では、予測モデル・勝率算出・EV閾値・集計定義・通知条件を変更しない。
前段で実装済みの採点品質ゲートやキャッシュ同期は維持する。

## 検証方法

最終回帰テスト: **1,012成功・2スキップ**（Windowsのsymlink権限と未設定のテスト用PostgreSQL）。
既存依存ライブラリの非推奨警告3件。`git diff --check` のエラーなし。

自動テストに加え、`tests/ui_preview.py` の架空データでPC幅と390px幅を確認した。
プレビューは本番用5005ポートと分離し、外部通信・DB接続・未定義APIを遮断する。
画面の「SAMPLE」は架空の検証用データであり、実際の予測成績ではない。

```powershell
$env:PYTHONUTF8='1'
python -B -m pytest tests -q -p no:cacheprovider --basetemp=.test-ui-check
python -B tests/ui_preview.py --port 5006
```

既存テストには過去のability.dbを読み取る特徴量テストが含まれる。
ブラウザ確認では、16頭すべて未採点の理由表示、WIN5の未取得→解析後頭数更新、
モデル別KPI、グラフの画面幅追従、ページ全体の横はみ出しを確認。

## 反映

Python側の統合画面テンプレートとWIN5 APIにも変更があるため、通常のローカル起動方法で
アプリを再起動し、ブラウザを強制再読み込み（Ctrl+F5）する。
プレビュー確認のために本番アプリ・監視ループ・通知を起動する必要はない。

## 追補: レース詳細のコース・風表示

- 12Rまでのボタンを40px固定・左右余白0にし、縮小による文字はみ出しを修正。
- コース図・風向き・直線/向こう正面の判定を、レース詳細のTOPへ移動。
- 大きな馬別EV表はその下の展開式パネルへ移動し、TOPのコース図を押し下げない。
- 各競馬場の公式平面図を大きく表示。全体/150%/200%の拡大、Escで閉じる、風の重ね表示切替を追加。
- 内外回りは距離から推測しない。新潟芝1000mは周回コース用の風バイアス・オーバーレイの対象外。
- 画像・風データの取得失敗を明示し、古い応答が別レースの表示を上書きすることを防止。

既存の画像対応表は、距離別の専用図ではなく各競馬場の全体平面図を参照している。
未確認の高解像度画像や架空のコース形状への差し替えはしていない。
公式のコース・距離の確認先: [阪神](https://www.jra.go.jp/facilities/race/hanshin/course/)、
[京都](https://www.jra.go.jp/facilities/race/kyoto/course/)、[新潟](https://www.jra.go.jp/facilities/race/niigata/course/)。

追補後の全体テストは **1,058成功・2スキップ**。PC/390px幅、12Rの実幅40pxと文字の収まり、
風の重ね表示、200%拡大とEsc復帰、レース切替、風データ欠測をSAMPLEプレビューで確認。
予測スコア・通知閾値・集計方法は変更していない。

この追補は静的HTML/CSS/JSの変更のため、通常はブラウザのCtrl+F5で反映できる。
本番アプリと監視ループは再起動していない。
