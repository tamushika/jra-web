# WIN5予想アプリ (ローカル) スコア算出・買い目生成仕様

対象: `jra_win5.py` + `index_win5.html`(port 5002、`start_win5.bat` で起動)
設定: [api/data_files/common/win5_weights.json](../api/data_files/common/win5_weights.json)(`use_ml: true`)
モデル: [api/data_files/common/win5_ml_model.json](../api/data_files/common/win5_ml_model.json)

Web版(複勝率ベース・オッズ不使用)とは独立した**勝ち馬予測特化**のスコアで、現在は**機械学習モデルが本番**。

## 1. スコア算出 — MLモード(現行)

実装: `scoring.compute_score_ml()`。**conditional logit(レース内softmax)** の線形結合:

```
スコア = Σ_i 係数_i × (特徴量_i − 平均_i) / 標準偏差_i × 10
勝率   = softmax(スコア / 10)  ← レース内で正規化 (キャリブレーション済み)
```

学習: 2021-2025・211,861出走(`backtest_ml.py`、ability.db)。内訳tooltipには寄与上位6特徴量を表示。

conditional logit は「1頭ずつ勝つ/勝たない」ではなく「同レースの他馬との相対比較」を
直接最適化する(2026-07に通常ロジスティック回帰から変更)。カバレッジは同等だが、
softmax出力がそのまま**レース内勝率**として使える(2025年OOSで予測カバレッジと実測の
乖離1〜2pt)。この勝率がレース固有の買い目配分(§3)の入力になる。

### 特徴量(20個)と学習済み係数(conditional logit)

| 特徴量 | 内容 | 係数(標準化後) |
|---|---|---|
| ln_odds | **単勝オッズの対数(市場)** | **−1.502(支配的)** |
| dist_pts | 距離変更バイアス点(db-keiba) 〔2026-07追加〕 | **+0.127(騎手と同格)** |
| j_pts | 騎手バイアス点(db-keiba勝率ベース) | +0.124 |
| f_pts | 枠バイアス点(同上) | +0.097 |
| affi_pts | 所属(美浦/栗東)バイアス点 〔追加〕 | +0.088 |
| prev_rank | 前走着順 | +0.071(逆張り: 市場の前走過剰反応を突く) |
| course_fit | 直近4走に同場同芝ダ同距離で3着以内 〔追加〕 | **−0.056(市場が過大評価→逆張り)** |
| tfeat | タイム指数(基準タイム+馬場差補正、直近4走の最良) | +0.044 |
| surf_pts | コース替わりバイアス点 〔追加〕 | +0.044 |
| cfeat | クラス実績 | −0.043(市場が織り込み過ぎのぶん引く) |
| grade_pts | 好走条件判定 ◎3/〇2/△1 〔追加〕 | +0.028 |
| agari_flag | 上がり上位30%経験 | −0.020 |
| wet_match | 道悪適性(当日道悪×相対適性 ±1) | −0.016 |
| pace_fit | 型PCI偏差×メンバー予測ペース 〔追加。ライブは0埋め=中立〕 | +0.013 |
| ln_interval | 出走間隔の対数 | +0.011 |
| n_prior | 直近走数 | +0.007 |
| age / is_male / kinryo / weight | 年齢/性別/斤量/馬体重 | ≒0(価値なし) |

- モデルが無い/例外時は手調整スコア(下記)へ自動フォールバック
- grade_pts の学習は血統以外ルールのみ(ability.db制約)、ライブは血統込み判定を使用
- pace_fit はレース全馬の集計が必要なためライブ推論では0埋め(CLはレース内一様シフト不変のため勝率に歪みなし)
- 血統辞典該当はML特徴量に含まれない(参考表示のみ)

### 非線形モデル(LightGBM)の検証結果 — 不採用

`backtest_ml.py --lgbm` でLambdaRank(レース内ランキング学習)を比較可能。
2026-07検証: k=1 31.8%(CL比+0.5pt)だがk=2/k=4は−0.5pt、平均54.1% vs 54.2%で同等。
best_iteration=28の浅さは現特徴量では関係がほぼ線形であることを示す。
依存追加に見合わないため不採用。血統等の新特徴量投入時に再評価する。

### 温度キャリブレーション

softmax勝率の過信/過小を補正する温度 τ を、学習内分割(21-23学習→24調整)の
条件付き尤度最大化で決定し `prob_temperature` としてモデルに保存(現行 τ=1.00=補正不要)。
再学習ごとに自動で再調整される。

### 検証(時系列アウトオブサンプル: 学習2021-24 → 検証2025)

| モデル | k=1 | k=2 | k=3 | k=4 |
|---|---|---|---|---|
| 手調整(オッズ統合済み) | 28.5% | 48.5% | 61.0% | 70.6% |
| ML 14特徴量(旧) | 30.7% | 50.6% | 63.4% | 72.4% |
| **ML 20特徴量(採用)** | **31.3%** | **51.0%** | 63.1% | 71.5% |

(k=N: 勝ち馬がスコア上位N頭に入る確率。配分が主に使う k=1/k=2 を優先して採用判断)

## 2. スコア算出 — 手調整モード(フォールバック / use_ml: false 時)

Web版と同じエンジンを以下の差分で使用:
- **勝率ベース**(rate_key=win_rate、回収ボーナスは単回のみ)
- **市場統合**: `+8.0 × ln(10 / 単勝オッズ)`(±10クランプ)— 最重要項
- 能力のクラス実績は1着偏重(1着1.0/2着0.4/3着0.2)
- 好走条件の該当数ボーナス: 2件目以降 +2.0/件(上限+6.0)
- 血統辞典・道悪適性・判定ボーナスはWeb版と同じ

## 3. 買い目生成(点数指定 50/100/150/200)

### 荒れ度(course_upset.csv)

コースごとの荒れランク S/A/B/C を照合(コース→同場同surface最近距離→場全体→default の順にフォールバック)。

### カバレッジ(実測値・MLスコア基準・2021-2025)

`allocation.coverage` = 荒れランク別の「勝ち馬がスコア上位k頭に入る確率」実測:

| ランク | k=1 | k=2 | k=3 | k=4 |
|---|---|---|---|---|
| S(荒れ) | 27.2% | 43.9% | 58.3% | 67.5% |
| A | 32.3% | 51.1% | 63.0% | 71.4% |
| B | 34.9% | 54.0% | 66.2% | 75.9% |
| C(堅い) | 35.8% | 55.2% | 68.6% | 79.5% |

### 配分アルゴリズム — レース固有勝率ベース(現行、`scoring.allocate_picks_prob`)

conditional logit の softmax 勝率から各レースの「上位k頭に勝ち馬が入る確率」を
**そのレースのスコア分布から直接**推定し、k1..k5 を全探索(`Πk ≤ 指定点数` の下で
Π(上位k頭の勝率和) を最大化)。1強レースは自動でk=1、混戦レースに厚く配分される。

**2025年OOS検証(101日)での効果 — 荒れランク平均配分との比較:**

| 点数 | ランク平均配分(旧) | レース固有配分(新) |
|---|---|---|
| 50点 | 3.0% | 3.0% |
| 100点 | 3.0% | **5.0%** |
| 150点 | 5.0% | **7.9%** |
| 200点 | 5.0% | **10.9%** |

MLモデルが無い/旧形式の場合は従来の荒れランク別カバレッジ平均(`allocate_picks`)に
自動フォールバック。荒れ度ランクはバッジ表示として残る。

### 軸1頭固定オプション

prob配分では「最大勝率レース」、rank配分では「スコア1-2位差最大レース」を1点固定。
**レース固有配分では軸固定なしの方が的中率が高い**(配分自体が自信のあるレースを
自動で1点にするため。150点: 通常7.9% vs 軸固定5.9%)。軸オプションは点数圧縮用と
位置づける。

## 4. WIN5対象レースの自動取得

1. JRAのWIN5対象ページ(`racelist.html`)から5レースを特定
2. トップページ経由で各レースのカードURLを解決(`_find_win5_urls`)
3. 未解決レースは**同場・同日の取得済みカードページのレースナビから補完**(兄弟レースフォールバック)
4. それでも欠ける場合はURL手入力欄を表示

## 5. 運用上の注意

- **オッズは変動する**: MLの最重要特徴量が単勝オッズのため、購入直前(締切近く)にSTEP2「スコア計算」を再実行するほど精度が出る(バックテストは確定オッズ基準)
- 簡易モードのタイム/上がりは前走分のみ取得(バックテストは4走分 → 実運用はやや控えめに見る)
- 対象レース近似(バックテストの的中率は日曜R降順5レース近似・単勝オッズ積は配当プロキシ)

## 6. 再学習・データ更新

- **毎週**: 馬場差自動更新(GitHub Actions・月曜朝) / 日曜夜のDB登録(馬名つき、`jra_db_updater.py` 2026-07修正版)
- **血統蓄積(2026-07開始)**: 出馬表スクレイプのたびに (馬名, 父, 母父, 母) を Neon の
  `horse_pedigree` へ自動upsert(`api/pedigree_store.py`。`PEDIGREE_COLLECT=0`で無効化)。
  開催日に `python collect_pedigree.py` を実行すると全会場・全レースを一括収集できる。
  学習期間の出走馬を十分カバーした時点で血統をML特徴量に追加する(現状ability.dbに父が無いのが最大のデータ制約)
- **血統の過去分バックフィル**: `python backfill_pedigree_netkeiba.py --limit 8000` を
  数晩に分けて実行すると、2021年以降の全出走馬(約3.2万頭)の父/母父を netkeiba から収集できる
  (Phase A: 成績ページから馬ID収集 → Phase B: 馬ページから血統取得 → Neonへ。
  冪等・`--status`で進捗確認・連続失敗10回でブロック判定して自動停止)。
  全馬そろったら血統特徴量を backtest_ml に追加し LightGBM も再評価する
- **半年ごと**: GitHub Actionsがdb-keiba統計を自動更新+リマインダーIssueを起票 → ローカルで `retrain_all.bat` を実行(①netkeibaから全馬確定オッズをNeonに埋め戻し → ②Neonから馬名つき新データを ability.db に自動取込 → ③馬場差 → ④ML再学習(OOS検証つき) → ⑤カバレッジ再計測)。**TARGET等の外部エクスポートは不要**
- **オッズ埋め戻しが必須な理由**: JRA成績ページには勝ち馬の払戻しか無く、勝ち馬以外の確定オッズが欠損する。欠損のまま再学習すると支配的特徴量 ln_odds がリークして壊れる(2026-07に検出・修正)。`extend_ability_from_neon.py` は充填率90%未満で警告を出す
- 再学習時は出力される OOS検証結果が劣化していないことを確認してからコミットする
