## 保留タスク

### 2. 組み合わせ馬券 (ワイド・馬連) の期待値通知
**依頼**: 2026-07-08。期待値監視アプリで単勝・複勝以外 (ワイド/馬連等) の
期待値がある買い目も通知したい。**血統バックフィル優先のため着手を保留中。**

背景: MLの conditional logit はキャリブレーション済みのレース内勝率を出すので、
Harville 式で組み合わせ馬券の的中確率を導出でき、EV = モデル確率 × オッズ で
単勝と同じEV判定ができる。組み合わせはエッジが増幅される (2頭に各+10%の優位 →
馬連で約+21%) ため、単勝EVで市場に勝てている現状 (2025年 単勝回収158.6%) なら
有望。控除率は単勝20% vs 馬連/ワイド22.5% と僅差。

**着手順序 (このプロジェクトの流儀: 先にバックテスト)**:
1. **払戻データの埋め戻し**: netkeiba 払戻テーブルには馬連・ワイド・三連複の払戻が
   ある。`backfill_fukusho_netkeiba.py` と同じ経路で ability.db に quinella_pay /
   wide_pay 列を追加する新スクリプトを書く (当たり=実額・外れ=没収で回収率は正確に出る)。
   ※ netkeiba を約4,000リクエスト消費するため、**血統バックフィルと同時に走らせない**
   (両方ブロックされる)。血統完了後 or 血統を1〜2日休んで先に取得のどちらか。
2. **バックテスト**: 21-24学習CLの勝率 → Harville+減衰 (指数0.8前後、補正値は
   バックテストで決定) で馬連/ワイドの的中確率を算出、EV閾値別に実現回収率を検証
   (backtest_ev.py の構造を流用)。効かなければ通知は追加しない判断もあり。
3. **ライブ実装 (効いた場合のみ)**: JRAオッズページから馬連・ワイドのオッズ行列を
   取得するスクレイパー + 確率エンジンを jra_ev.py の compute_picks に追加。
   通知フォーマットに券種を追加。

**非推奨**: 三連単 (オッズ取得が数千通りで重い・分散が巨大でEV誤差が三乗で増幅)。
まずワイド (的中頻度が高く検証が早い) → 馬連の順が堅実。

## 一度だけ必要な設定 (人手)

- **Discord通知を使う場合**: `jra-web/.env` に `EV_DISCORD_WEBHOOK=<WebhookのURL>` を1行追加。
  (Discord: サーバー→チャンネル設定→連携サービス→Webhook作成でURL取得)。未設定なら通知はブラウザのみ。
- **LINE通知を使う場合** (5分前 × EV>=1.3 のみ送信。LINE Notifyは2025年終了のため Messaging API):
  1. https://developers.line.biz/ にLINEアカウントでログイン → プロバイダー作成
  2. 「Messaging APIチャネル」を作成 → Messaging API設定タブで
     **チャネルアクセストークン (長期)** を発行
  3. 同タブのQRコードで自分のLINEにボットを友だち追加
     (応答メッセージはオフ推奨。友だちは自分だけにする — broadcast配信のため)
  4. `jra-web/.env` に `EV_LINE_CHANNEL_TOKEN=<トークン>` を1行追加
  5. 疎通確認: `python jra_ev.py --test-line` (スマホにテスト通知が届けばOK)
  - 送信条件は `EV_LINE_STAGE` (既定5) / `EV_LINE_MIN_EV` (既定1.3) で変更可。
    無料枠200通/月 — 5分前のみ・閾値1.3なら月数十通で収まる見込み
- **.env に必須のもの** (既存): `DATABASE_URL` (Neon)、`GEMINI_API_KEY` (PDF抽出用)。
  これらは git 管理外。別PCで動かす場合は手動でコピーが必要。
