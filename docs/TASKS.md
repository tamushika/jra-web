**運用ルール**
- タスクが完了したら本表の「状態」を更新する (✅ + 日付 + 結果を1行。**負の結果も必ず記録**)。
- 週末の定例運用は本表ではなく HANDOFF.md「定例・運用タスク」を参照。

## 担当の割り振り方針

| 担当 | 割り振る作業 |
|---|---|
| **Codex** | 仕様が明確なコード実装 (スクレイパー、特徴量生成、テスト、UI、リファクタ)。仕様書は上位モデルが書き、成果物は上位モデルがレビューしてからコミット |
| **下位モデル** (Sonnet等) | スクリプトの実行・集計・結果の一次整理、定型的な調査、ドキュメント更新 |
| **上位モデル** (Fable/後継) | 仕様策定、**検証結果の採否判断** (OOS数値の解釈・採用ゲート照合は必ずここ)、CodexOutput/下位モデル出力のレビュー |
| **人手** | 環境操作 (.env、タスクスケジューラ)、日次制限つきスクレイプの日またぎ実行、週末の実運用確認、馬券購入 |

原則: **実装と判断を分離する**。実装は Codex/下位モデルへ、採否判断とレビューは上位モデルへ。検証の作法 (時系列OOS → 採用ゲート → 負の結果も記録) は roadmap §8 と HANDOFF 末尾を参照。
