生成元: `backtest_t70c_gate.py`（読み取り専用、`data/jra_logging.db` の
`virtual_bets` のみを入力。`mode=ro` + `PRAGMA query_only=ON`）。
生成日時 (UTC): 2026-10-14T14:25:41.608160+00:00 — 元データの `as_of_date`
(全ポリシー中の最新 `date`) は `20261012`。

本レポートは **採否・実マネー移行の是非を判定しない**。判定とレビュー担当の
裁定は別フィールド (`machine_judgment` と `reviewer_adjudication: null`)。
**`GATE_PASS` であっても実マネー移行の承認ではない** — 移行は別途ユーザー承認
+ 規約リスク調査 (T70 P4) を要する。

## 1. 機械判定 (P1 = `policy_version='v1'`)

**`machine_judgment = INVALID`**

理由 (fail-closed, SPEC-T70c §2-3 / §4):

> settled-only population does not meet the n condition after excluding
> pending rows (event_days=15 < 12 and/or main_bets=24 < 30; pre-exclusion
> was event_days=16, main_bets=27)

本体ベット (`is_control=0`) は pending 3 件を除外すると settled のみで
15 開催日・24 件となり、n 条件 (12 開催日以上 **かつ** 30 件以上) の
「30 件以上」を満たさない。これは SPEC-T70c §2-3・§4 の INVALID 規則
（「精算済みだけで n 条件を満たさない」）に直接該当するため、GATE_PASS /
GATE_FAIL ではなく **INVALID** で停止する。

以下の5条件の数値は、INVALID の根拠を示す **診断値** として出力されている
(`conditions_note` 参照)。ゲート通過・不通過の判定そのものではない。

## 2. 事前登録5条件の数値 (診断値。判定根拠はINVALID)

| # | 条件 | 観測値 | 閾値 | 成否 |
|---|---|---|---|---|
| 1 | n: 開催日≥12 **かつ** 本体ベット≥30件 (settled-only) | 15開催日・24件 (除外前: 16開催日・27件) | 12開催日・30件 | 不成立 → **INVALID** |
| 2 | 本体複勝ROI点推定 ≥ 100% | 87.08% (払戻¥41,800 / 投資¥48,000・n=24) | 100% | 不成立 |
| 3 | 開催日ブロックbootstrap (2000回・seed=70) の ROI下側5%点 ≥ 85% | 70.42% (95%CI: 66.25%〜108.01%、ブロック数15) | 85% | 不成立 |
| 4 | 対照 (選定レース1番人気複勝) のROIを上回る | 本体87.08% vs 対照87.08% (**同値**。差の点推定0.0、paired bootstrap 95%CI [0.0, 0.0]) | 本体 > 対照 | 不成立 (同値のため「上回る」を満たさない) |
| 5 | 最大払戻1件を除外してもROI ≥ 90% | 83.91% (除外対象: 20260822:札幌:12、horse_number=11、payout=¥3,200) | 90% | 不成立 |

**特記事項**: 条件4で本体と対照のROIが完全に一致している。実データを確認した
ところ、settled 24件全てで CL勝率1位馬の馬番・オッズが対照 (1番人気) と
完全一致していた。つまり直近のサンプルでは「CL勝率1位モデル」が選んだ馬は
毎回そのレースの単純なオッズ最小人気馬と同一であり、現時点のサンプルでは
選定の付加価値が確認できていない (これは観測事実の報告であり、採否の裁定
ではない)。

## 6. 制限・解釈上の注意

1. **サンプルがそもそも不足**: 本体ベット (settled) 24件・15開催日は、
   事前登録されたn条件 (30件・12開催日) の件数要件に達していない。
   SPEC-T70冒頭の「件数条件が到達した」という記述は本体+対照の合計54件
   (精算済48・保留6) を指しており、本体のみの件数 (settled 24件、
   pending込みでも27件) は30件に未到達。本ハーネスは件数の数え方を
   変更せず、SPEC-T70c §0の条件文言 (「本体ベット30件以上」) をそのまま
   機械的に適用した結果として INVALID と判定した。
2. **`refunded` 行のn条件への扱いは本ハーネス独自の解釈**: SPEC-T70c §2は
   `pending` と `skipped_budget` の扱いのみを明示し、`refunded` には
   触れていない。本ハーネスは `refunded` を n 条件 (pending+settledの
   カウント) にも ROI 計算にも含めない (`skipped_budget` と同様「母集団外」
   として件数のみ報告) 解釈を採用した。実データ (v1) には `refunded` 行が
   無く、この解釈の採否は結果に影響していないが、レビュー時に確認が必要。
3. **保留行の「理由」は推定**: SPEC §1 が許可する列 (`date` 等) のみから
   機械的に分類した相対的な区分 (直近=同期待ちの可能性 / 長期=異常の
   可能性) であり、`race_results` 等を参照した確定診断ではない。
4. 本レポート・`outputs/t70c/gate_report.json` は稼働中サーバー・本番DB・
   `docs/TASKS.md`・`eval/experiments.jsonl` を変更していない。
